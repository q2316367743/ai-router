# 本地代理服务

> 核心功能：监听 `127.0.0.1:<port>`，凭全局 API Key 对外提供 OpenAI 兼容服务，按模型映射反向代理到上游提供商。代码在 `src/main/src/server/`（Express 5 + 全局 `fetch`；CORS / 鉴权 / 路由组装在 `proxyRouter.ts`，转发与流式透传在 `proxyHandler.ts`）。

## 生命周期

- 启动：`main/index.ts` `whenReady` 中 `ensureServiceDefaults() → cleanupLogsOnStartup() → await startProxyServer()`（服务开关关闭时只更新状态、不监听）。
- 重启：渲染层「服务设置」保存端口/开关后，`serviceIpc` 的 `service:saveConfig` 内调用 `restartProxyServer()`。Key 变更无需重启（每请求实时读库）。
- 退出：`app.on('will-quit')` → `stopProxyServer()`（`close` + `closeAllConnections`）。
- 端口占用（EADDRINUSE）不崩溃，状态置 `error` 并广播。

## 状态推送

`proxyServer.ts` 的 `updateStatus()` 在状态变化时 `BrowserWindow.getAllWindows().forEach(w => w.webContents.send('server:status', status))`；渲染层经 `window.preload.service.onStatusChanged(cb)` 订阅（通道 `server:status`，载荷 `ServiceStatus`）。

## 请求处理流程（`proxyRouter.ts` 组装，`proxyHandler.ts` 转发）

```
OPTIONS            → CORS 中间件直接 204 + 预检响应（其余响应统一 setHeader 放行来源）
鉴权中间件失败     → 401 {error:{type:'authentication_error', code:'invalid_api_key'}} + 记日志
GET  /v1/models    → 本地生成 {object:'list', data:[…]}（仅启用映射；owned_by=提供商名）
POST /v1/*         → express.json 解析 body(≤32MB) → 取 model 查映射 → 替换 model 后转发上游
其余 method/path   → 404
```

中间件顺序：CORS → 鉴权 → 路由（`app.get('/v1/models')`、`app.post(/^\/v1\//, express.json(...))`）→ 404 兜底 → 错误兜底中间件。转发路由的异常经 `.catch(next)` 进入错误兜底，任何分支都不向客户端抛异常。

1. **鉴权**：兼容 `Authorization: Bearer <key>` 与 `x-api-key` 两种头；Key 来自 `settingRepo.getServiceConfig()` 实时读取。
2. **映射**：`modelRepo.findMapping(publicName)` 一次联表返回 `MappingRoute`（上游模型名 + 提供商 baseUrl/apiKey + 双方 enabled）。映射或提供商任一禁用 → 404 `model_not_found`（对外表现为模型不存在）。
3. **转发**：`fetch(baseUrl(去尾斜杠) + 原始 path(含 query))`；**除 `model` 字段替换外请求体原样透传**；请求头白名单只带 `content-type` / `accept`，`authorization` 替换为上游 Key。
4. **响应透传**：
   - 非流式：读完上游 body 一次性回写（状态码 + content-type 原样）。
   - 流式（content-type 含 `text/event-stream`）：`writeHead` 后逐块 `res.write` 回写，`write` 返回 false 时等 `drain` 背压；客户端断开（`res.on('close')` 且未写完）时 `AbortController.abort()` 中断上游。
5. **usage 提取**（不阻塞透传）：非流式 `JSON.parse` 取 `usage`；流式用 `createSseUsageFeeder()` 按完整行解析 `data:` 行，取最后一个非空 `usage`（`[DONE]` 跳过）。`total_tokens` 缺失时用 prompt+completion 补齐。
6. **落库**：结束后写 `request_logs`（元数据 + 非 2xx 时响应前 500 字符入 `error` 字段）+ `usage_daily` 累加（**仅 upstream.ok 时记用量**，失败请求 tokens 不可信）。401/404/502 等本地拦截也记日志（未知字段填 `-`）。落库失败静默，不影响代理。

## 错误格式

统一 OpenAI 风格，所有响应带 `access-control-allow-origin: *`：

```json
{ "error": { "message": "…", "type": "authentication_error | invalid_request_error | api_error", "code": "…" } }
```

| 场景 | 状态码 | type / code |
|------|--------|-------------|
| Key 错误 | 401 | `authentication_error` / `invalid_api_key` |
| body 非 JSON / 缺 model | 400 | `invalid_request_error` |
| body 超 32MB | 413 | `invalid_request_error` |
| 模型未映射/禁用 | 404 | `invalid_request_error` / `model_not_found` |
| 上游网络失败 | 502 | `api_error` |
| 上游返回 | 原样透传上游状态码与 body | — |

body 超 32MB / 非法 JSON 由 `express.json` 抛错（413 / 400），错误兜底中间件统一转上表 OpenAI 风格；非对象 body（数组/标量）在 `forwardRequest` 内拦截为 400。

## 注意事项

- 无请求总超时：长流式回答不设上限，靠客户端断开驱动 abort。
- CORS 由中间件统一处理：预检 204 放行所有来源（服务自身有 Key 鉴权），其余响应 `setHeader` 放行来源，`proxyHandler.ts` 内不再逐响应补头。
- 转发刻意使用白名单请求头，避免把 `host`/`content-length`/cookie 等透传给上游引发 4xx。
- 流式透传用 `reader.read()` 手动泵而非 `Readable.fromWeb`，规避 DOM/Node 流类型桥接断言。
- `proxyHandler.ts` 只依赖 `node:http` 类型（`IncomingMessage & { body?: unknown }`），不 import express 类型，避免与 fetch 的全局 `Response` 重名；框架类型只存在于 `proxyRouter.ts`。
- `proxyServer.ts` 用 `createProxyApp().listen(port, '127.0.0.1')` 拿到 `http.Server` 句柄，`close` + `closeAllConnections` 的关闭语义不变。
