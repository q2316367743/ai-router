# 协议适配与转换（策略 = 双向编解码器）

> 核心功能：对外同时暴露三个协议入口（OpenAI Chat `/v1/chat/completions`、Anthropic Messages `/v1/messages`、OpenAI Responses `/v1/responses`），上游按提供商「接口类型」支持同三种协议。**策略 = 一个协议的双向编解码器**（2026-09-19 二次重构：策略可入可出，任意「入口协议 × 上游协议」组合；同协议 raw 透传，异协议经统一会话转换；出站 axios 直连，无 SDK）。代码在 `src/main/src/server/strategies/`。

## 协议矩阵（3 × 3）

| 入口 ↓ \ 上游 → | openai | openai-responses | anthropic |
|------------------|--------|------------------|-----------|
| **openai**（/v1/chat/completions） | raw 透传 | 转换 | 转换 |
| **openai-responses**（/v1/responses） | 转换 | raw 透传 | 转换 |
| **anthropic**（/v1/messages） | 转换 | 转换 | raw 透传 |

- **raw 透传**（对角线）：body 除 `model` 外原样转发、响应原样回写——未知字段零损失（如 `response_format` 等协议专属参数在透传下天然可用）。
- **转换**：入口解析为统一会话 → 上游构建报文 → 上游解码为统一事件/结果 → 入口编码回写。

## 策略接口（`strategies/types.ts`）

```ts
interface ProtocolStrategy {
  readonly protocol: ProviderProtocol
  // ── 入口方向：该协议作为对外接口 ──
  parseRequest(body): Conversation                     // 请求体 → 统一会话（不合规 → 400）
  encodeCompletion(res, model, completion)             // 统一结果 → 非流式响应体
  createEntryEncoder(res, model): EntryEncoder         // 统一事件 → 该协议 SSE（惰性头 + 背压 + 终止帧）
  writeError(res, status, message, code?)              // 该协议的错误信封
  // ── 上游方向：该协议作为提供商接口 ──
  buildRequest(conversation, route, extraHeaders): WireRequest
  decodeResponse(payload): Completion                  // 非流式 JSON → 统一结果（宽松，供透传抽 usage 复用）
  createUpstreamDecoder(onEvent): UpstreamDecoder      // 上游 SSE → 统一事件（sink 注入，与入口解耦）
  // ── 同协议透传的传输特征 ──
  readonly upstreamPath: string                        // /chat/completions | /messages | /responses
  upstreamAuthHeaders(route)                           // 透传时在客户端头之上替换/追加的鉴权与协议头
}
```

**统一会话与流事件（`strategies/conversation.ts`，协议中性枢纽）**：

- `Conversation`：stream / system / messages（user 文本+图片 / assistant 文本+toolCalls / tool_result）/ tools / toolChoice / temperature / topP / maxOutputTokens / stopSequences / reasoningEffort。
- `StreamEvent`：text / reasoning / tool-start / tool-delta / tool-complete / finish（finishReason + usage）。
- `Completion`：content / reasoning / toolCalls / finishReason / usage（流式 finish 与非流式共用）。
- `FinishReason` 中性词表 stop/length/tool_calls/content_filter，各协议自行映射。
- `ApiUsage` 统一用量（缓存读/写、思考明细可缺省），`toTokenUsage()` 供日志落库。

## 分发与转发层

```
routes/entry.ts 工厂（校验 body/model → findRoutes → 归档 404 / 禁用 404 / 全阻断 503，均按入口协议信封）
→ balancer 选路（可用度排序 + 会话亲和，见 ../app/15-负载均衡与故障转移.md）
→ forward.ts 尝试循环（2026-09-23 起）：entry = strategyOf(入口协议)；upstream = strategyOf(route.providerProtocol)
   每个候选按各自协议分发 → entry === upstream ? passthrough.ts（同协议 raw 直通）: converted.ts（异协议转换）
   执行器返回 AttemptOutcome；未提交的失败扣可用度并改道下一候选，已提交或请求侧错误则就此收口
```

- **passthrough.ts**：raw body（仅换 model）+ 客户端头全量透传（黑名单剥离 + `upstreamAuthHeaders` 替换鉴权）+ 原样回写；`stream` 按客户端意愿预估、以实际上游 content-type 回填。**usage 提取也经策略完成**：流式把同一份字节喂给 `upstream.createUpstreamDecoder` 做「抽头」（事件不回写，只从 finish 收 usage）；非流式 `upstream.decodeResponse(JSON.parse(body)).usage`。
- **converted.ts**：pending 日志 → `entry.parseRequest`（在尝试循环外只解析一次；抛 `ChatParseError` → 400）→ `upstream.buildRequest`（报文即线上捕获）→ axios（`validateStatus` 全放行）→ 非 2xx 读全量错误体按真实状态码 + 入口信封返回；流式 `upstream 解码 → 统一事件 → entry 编码回写`（惰性头，头未写前出错可改道协议错误信封，已写则流内错误帧）；非流式读全量 JSON → `upstream.decodeResponse` → `entry.encodeCompletion`。abort → 499；网络错 → 502（拦截器增强消息）；流在终态事件前中断 → 502 `Upstream stream ended unexpectedly`。**提交前**的这些失败都还归 `forward.ts` 的改道循环处置（响应头惰性 + 错误体先缓冲），**提交后**才就地收口。

## 每协议五件套（`strategies/<protocol>/`）

| 文件 | 方向 | 职责 |
|------|------|------|
| `parse.ts` | 入口 | 线上请求体 → 统一会话（校验与 400 语义） |
| `encode.ts` | 入口 | 统一事件 → SSE 编码器；统一结果 → 非流式 JSON；协议错误信封 |
| `request.ts` | 上游 | 统一会话 → 上游报文（含协议专属参数映射） |
| `decode.ts` | 上游 | 上游 SSE → 统一事件；上游 JSON → 统一结果 |
| `index.ts` | — | 组装 `ProtocolStrategy`（registry.ts 唯一注册点，新增协议 = 加目录 + 注册一行） |

透传流不经过 parse/request/decode/encode（raw 直通），五件套服务于该协议作为「异侧」的所有组合。

## 协议映射要点

**OpenAI Chat**（`openaiChat/`）：

- parse：system/developer 归并、user 分段（text/image_url）、assistant `tool_calls`、`role:'tool'` 结果（toolName 由前置 assistant 调用补全）、`max_completion_tokens`/`max_tokens`、`stop`、`reasoning_effort`；仅支持 n=1。
- encode：`chat.completion.chunk` SSE（首块 role、reasoning_content 用 DeepSeek 约定字段、tool_calls 按 id→index 增量、finish 后独立 usage 块 + `[DONE]`）；非流式 `chat.completion`；流内错误 `data:{"error":{…}}`。
- request：system → 首条 system 消息；tool_result → `role:'tool'`；`max_tokens` / `stop` / `reasoning_effort` 直通。
- decode：delta.content / reasoning_content / tool_calls 按 index 聚合（id+name 聚齐才发 tool-start）；finish_reason 与 usage 尾块在 `[DONE]` / 流末合成 finish（兼容不发 `[DONE]` 的网关——有 finish_reason 即在 flush 时补发 finish，没有则视为异常中断）。

**Anthropic Messages**（`anthropicMessages/`）：

- parse：system（字符串/块合并）、text / image（base64 source 还原为 data URL、url source 原样）、assistant `tool_use`、user 内 `tool_result` 块、`thinking.budget_tokens` → reasoning_effort 阈值反推（≥10000→high、≥4096→medium、否则 low，**有损**）；`tool_choice` any→required。
- encode：`message_start`（惰性）→ content_block_start/delta/stop（text_delta / thinking_delta / input_json_delta，块类型切换自动收口）→ `message_delta`（stop_reason + 输出 usage）→ `message_stop`；错误 → `event: error`；stop_reason 反向映射（stop→end_turn、length→max_tokens、tool_calls→tool_use、content_filter→refusal）。**限制**：`message_start.usage.input_tokens` 恒 0（流式时序下 usage 在 finish 事件才可知），输出 token 随 message_delta 下发。
- request：system 顶层字段、`tool_use`/`tool_result` 块（连续 tool_result 合并进同一 user 消息）、`input_schema`、tool_choice auto→auto / required→any / 指定→tool（**none 无对应取值 → 不传**）、thinking 预算 1024/4096/10000（启用时省略采样参数、max_tokens ≥ 预算+1024、默认 4096）、`x-api-key` + `anthropic-version: 2023-06-01`。**思考历史不回传**（signature 不可再造）。
- decode：message_start（输入 usage）→ content_block_start/delta/stop（block index 关联工具 id）→ message_delta（stop_reason + 输出 usage）→ message_stop；error 事件 → 流内失败。usage：prompt = input_tokens + cache_read + cache_creation（明细分列）。

**OpenAI Responses**（`openaiResponses/`）：

- parse：`instructions` → system；input 项 message / reasoning / function_call / function_call_output；`reasoning.effort`；`tool_choice` 直通；**仅支持 function 工具**（内置工具报 400）；`item_reference` 不支持（代理无状态）。
- encode：`response.created`（惰性）→ message/reasoning/function_call 输出项（output_item.added → 增量帧 → output_item.done）→ `response.completed`（重建 output 数组 + usage）；错误 → `data:{"type":"error",...}`。
- request：system → `instructions`；assistant tool_calls → `function_call` 项（call_id + arguments 字符串）、tool_result → `function_call_output`；`store:false`（无状态代理）；**stop 序列不支持丢弃**；思考历史不回传（非加密 reasoning 项会被上游拒绝）；Bearer 认证。
- decode：`response.output_text.delta` → 文本、`reasoning_summary_text.delta` / `reasoning_text.delta` → 思考、`refusal.delta` → 文本、function_call 项（item_id 关联 call_id）→ 工具增量；`response.completed`/`incomplete`（max_output_tokens→length）收口；`response.failed`/`error` → 流内失败。usage：cached_tokens → 缓存读、reasoning_tokens → 思考明细。

## 错误信封

- **路由内错误**（body 非法 400、模型 404、上游错误回包）按**入口协议**信封：openai → `{error:{message,type,code}}`；anthropic → `{type:'error',error:{type,message}}`；responses → `{error:{code,message,param}}`。
- **全局拦截**（401 鉴权、413 超限、未知路由 404，在 `app.ts` 中、协议路由之前）统一 OpenAI 信封。
- 转换路径的上游 4xx/5xx：真实状态码 + 入口信封包裹正文前 300 字摘要；透传路径上游错误原样透传。

## baseUrl 语义（`upstream/urls.ts`）

**统一约定：提供商 `baseUrl` = 完整 API 根**（含 `/v1`、`/api/plan/v3`、中转站自定义前缀等），代理**不做版本推断、不自动补 `/v1`**；端点路径由策略提供（`joinEndpoint` 转换 / `joinEndpointWithQuery` 透传保留入站 query）。上游根地址需由用户在提供商配置页填全，例如 `https://api.anthropic.com/v1`、`https://api.openai.com/v1`。

## 与日志的关系

三条策略共用 `logging/requestLog.ts` 同一落库管线与「线上口径」：转换路径请求侧 = 策略构建的出站报文（`wireCapture.ts` 捕获对象直接赋值），透传路径 = 换完 model 的 raw body；响应侧均为提供商原始返回（流式为全部 SSE 文本，边读边累积，中断保留已收部分）；标头入库前脱敏（`authorization` / `x-api-key` / `cookie` / `set-cookie` 剔除）；pending 行先落、结束时按 requestId upsert 回填并累加 usage_daily / usage_hourly；未发起上游请求的同步拦截分支请求侧记 null。

## 已知限制（转换路径；同协议透传不受影响）

- 转换经统一会话，各协议特有字段不透传：responses 的 `store` / 内置工具（web_search 等）/ `item_reference`；anthropic 的 citations 等。
- Anthropic 入口 thinking 预算反推 effort 有损；思考历史在任何转换路径都不回传。
- Anthropic 入口流式 `message_start.usage.input_tokens` 恒 0。
- 非流式回包由统一结果合成，协议字段为最小合法形态（如 anthropic thinking 块无 signature）。
- Responses 上游 `stop` 序列不支持被丢弃；anthropic 上游 `tool_choice:'none'` 退化为不传。
