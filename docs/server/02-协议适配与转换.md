# 协议适配与转换

> 核心功能：对外统一暴露 OpenAI Chat Completions 入口，上游按提供商「接口类型」支持三种协议（OpenAI Chat / OpenAI Responses / Anthropic Messages）。同协议纯透传保真；异协议经 **ai-sdk 中间层**（`ai@7` + `@ai-sdk/openai` + `@ai-sdk/anthropic`）双向转换。代码在 `src/main/src/server/protocol/`。

## 协议矩阵

| 客户端（固定） | 上游接口类型 | 路径 | 实现 |
|----------------|--------------|------|------|
| OpenAI Chat | `openai` | 纯透传 | `proxyHandler.ts` 原有逻辑（仅替换 `model` 字段） |
| OpenAI Chat | `openai-responses` | ai-sdk 转换 | `createOpenAI({baseURL}).responses(model)` |
| OpenAI Chat | `anthropic` | ai-sdk 转换 | `createAnthropic({baseURL})(model)`，SDK 自动携带 `x-api-key` + `anthropic-version` |

## 数据流（转换路径）

```
client(openai chat JSON)
→ proxyRouter 显式路由 POST /v1/chat/completions
→ forwardRequest 查映射 → route.providerProtocol !== 'openai'
→ forwardConverted (protocol/convertHandler.ts)
   1. parseChatPrompt  chatRequest.ts  OpenAI Chat JSON → ai-sdk ModelMessage/tools/settings
   2. planUpstream     upstream.ts     按协议建模型实例（baseUrl 视为完整 API 根）
   3. streamText                       统一 fullStream（tools 不带 execute → 不执行工具）
   4. streamToClient / bufferToClient  统一流 → OpenAI Chat 线上格式（chatResponse.ts）
   5. recordRequest 统一落库      复用 proxyLog.ts（日志 + 用量聚合），usage 来自 ai-sdk 统一 usage
```

## 模块职责（`src/main/src/server/protocol/`）

| 文件 | 职责 |
|------|------|
| `types.ts` | OpenAI Chat 解析产物 `ChatPrompt`、协议相关类型、`ChatParseError` |
| `chatRequest.ts` | `parseChatPrompt()`：请求体 → 提示与参数；system/developer 归并、user 分段（text/image_url）、assistant `tool_calls` → tool-call part、`role:'tool'` → tool-result（toolName 由前置 assistant 调用补全）；`max_completion_tokens`/`max_tokens` → `maxOutputTokens`；`stop` → `stopSequences`；不合规结构抛 `ChatParseError` → 400 |
| `upstreamUrl.ts` | 上游端点解析：统一约定 baseUrl = 完整 API 根；`normalizeBaseUrl()`（去尾斜杠，不补版本段）；`joinChatCompletionsUrl()`（API 根 + `/chat/completions`，保留 query）供透传路径；`joinConvertUrl()`（API 根 + `/messages` / `/responses`）；`upstreamPathOf()` 取 URL 的 pathname+query 供日志 `path` 使用 |
| `upstream.ts` | `planUpstream()`：按协议构造模型实例 + provider 专属参数计划；Anthropic thinking 预算映射（low 1024 / medium 4096 / high 10000，启用时禁用采样参数并保证 `max_tokens` > 预算）；baseURL 经 `normalizeBaseUrl()` 规范化 |
| `chatResponse.ts` | `createChunkWriter()`：统一流 → SSE 块写出器（惰性响应头，内部累积下发文本供 `dump()` 采集日志响应正文）；`sendChatCompletion()`：非流式聚合响应（返回写出正文）；finish_reason / usage（含明细）映射 |
| `convertHandler.ts` | `forwardConverted()`：主流程、abort 传递、上游错误映射（`APICallError.statusCode` → 状态码，其余 502）、日志落库 |

## 线上格式约定

- **流式**：`chat.completion.chunk`；首块 `delta:{role:'assistant',content:''}`；`text-delta→content`、`reasoning-delta→reasoning_content`（DeepSeek 约定字段，主流客户端可读）；工具调用优先按 `tool-input-start/delta` 增量下发 `delta.tool_calls[].function.arguments`（id→index 映射），上游未给增量时整段下发完整 `tool-call`；`finish_reason` 块后补独立 usage 块（`choices:[]`，等价 OpenAI `include_usage`）+ `data: [DONE]`
- **流内错误**：响应头未写出前发现错误 → 直接以真实状态码返回 JSON 错误信封；已开始流式后出错 → `data:{"error":{…}}` + `[DONE]`
- **非流式**：`chat.completion`，`message.reasoning_content` / `message.tool_calls` 按需出现
- **abort**：客户端断开 → `abortSignal` 中止上游，日志记 status 499、不计用量

## 请求头透传

客户端自定义请求头（UA、`x-request-id`、`x-session-id`、`anthropic-beta` 等）原样转发上游，两条路径共用黑名单剥离（`forwardHeaders.ts`）：

- **透传路径**：`buildForwardHeaders()`——客户端头全量附带 + `authorization` 替换为上游 Key
- **转换路径**：`collectExtraHeaders()` 再剥离 `content-type` / `accept`（SDK 自建），其余经 `createAnthropic` / `createOpenAI` 的 `headers` 选项附带（SDK 的认证头不冲突）
- 两路径均剥离逐跳头与 `authorization` / `x-api-key` / `cookie`（客户端访问本代理的 Key 不得泄漏给上游）
- CORS 预检的 `allow-headers` 回显客户端申请的头（浏览器类客户端自定义头不被预检拦截）

## baseUrl 语义（`upstreamUrl.ts`）

**统一约定：提供商 `baseUrl` = 完整 API 根**（含版本/路径前缀，如 `/v1`、`/api/plan/v3`，以及国内中转站的自定义前缀），代理**不做版本推断、不自动补 `/v1`**。两条路径共用此语义：

- **透传路径（`openai`）**：`joinChatCompletionsUrl()` = API 根 + `/chat/completions`（保留入站 query）。
- **转换路径（`openai-responses` / `anthropic`）**：`normalizeBaseUrl()` 仅去尾斜杠，SDK 自行追加 `/responses`、`/messages`。

因此上游根地址需由用户在提供商配置页填全（配置页 help 已提示）。例如 `https://api.anthropic.com/v1`、`https://api.openai.com/v1`、`https://ark.cn-beijing.volces.com/api/plan/v3`。

## 已知限制（转换路径）

- 仅支持 `n=1`（>1 返回 400）
- 忽略 OpenAI 专属参数：`response_format` / `logprobs` / `prediction` / `stream_options` 等（透传路径不受影响）
- `reasoning_effort`：`minimal` 不启用 thinking；`low/medium/high` 映射 Anthropic thinking 预算或透传 Responses `reasoningEffort`
- Anthropic 上游强制 `max_tokens`：客户端未传时默认 4096
- 不透传客户端自定义请求头（认证头由 SDK 按 upstream 协议重建）

## 与日志的关系

转换路径复用 `proxyLog.ts` 同一落库管线，采集口径与透传路径一致：

- **usage**：取自 ai-sdk 统一 `LanguageModelUsage`，`toTokenUsage()`（`chatResponse.ts`）映射 `inputTokens/outputTokens` 及明细 `inputTokenDetails.cacheReadTokens/cacheWriteTokens`（缓存读/写）、`outputTokenDetails.reasoningTokens`（思考）；线上 `usage` 块仍只含 `prompt_tokens/completion_tokens/total_tokens`，明细仅入日志与用量聚合。提供商未返回用量时的兜底估算在 `recordRequest()` 统一处理（估算一次，日志与聚合共用）。
- **响应正文**：流式由 `createChunkWriter()` 内部累积实际下发的全部 SSE 文本（`writer.dump()`），非流式由 `sendChatCompletion()` 返回写出的 JSON 文本；错误分支捕获 `sendOpenAiError()` / 流内 error 块正文。
- **响应标头**：成功取 `await result.response` 的 `headers`，上游错误取 `APICallError.responseHeaders`；本地拦截（解析 400 等）为 null。
- **路径**：日志 `path` 由 `joinConvertUrl()` + `upstreamPathOf()` 推导上游实际请求路径（API 根 + `/messages` / `/responses`），非客户端入口路径。
- **请求上下文**：`requestId` / 请求正文 / 脱敏请求标头由 `forwardRequest()` 采集后经 `ForwardConvertedOptions` 传入。
