# 协议适配与转换

> 核心功能：对外统一暴露 OpenAI Chat Completions 入口，上游按提供商「接口类型」支持三种协议（OpenAI Chat / OpenAI Responses / Anthropic Messages）。同协议纯透传保真；异协议经 **ai-sdk 中间层**（`ai@7` + `@ai-sdk/openai` + `@ai-sdk/anthropic`）双向转换。代码在 `src/main/src/server/protocol/`。

## 协议矩阵

| 客户端（固定） | 上游接口类型 | 路径 | 实现 |
|----------------|--------------|------|------|
| OpenAI Chat | `openai` | 纯透传 | `proxyHandler.ts` 原有逻辑（仅替换 `model` 字段） |
| OpenAI Chat | `openai-responses` | ai-sdk 转换 | `createOpenAI({baseURL}).responses(model)` |
| OpenAI Chat | `anthropic` | ai-sdk 转换 | `createAnthropic({baseURL})(model)`，SDK 自动携带 `x-api-key` + `anthropic-version` |

## 数据流（转换路径）

```
client(openai chat JSON)
→ proxyRouter 显式路由 POST /v1/chat/completions
→ forwardRequest 查映射 → route.providerProtocol !== 'openai'
→ forwardConverted (protocol/convertHandler.ts)
   1. parseChatPrompt  chatRequest.ts  OpenAI Chat JSON → ai-sdk ModelMessage/tools/settings
   2. planUpstream     upstream.ts     按协议建模型实例（baseUrl 补 /v1）
   3. streamText                       统一 fullStream（tools 不带 execute → 不执行工具）
   4. streamToClient / bufferToClient  统一流 → OpenAI Chat 线上格式（chatResponse.ts）
   5. recordLocalLog / addUsageQuietly 复用 proxyLog.ts，usage 来自 ai-sdk 统一 usage
```

## 模块职责（`src/main/src/server/protocol/`）

| 文件 | 职责 |
|------|------|
| `types.ts` | OpenAI Chat 解析产物 `ChatPrompt`、协议相关类型、`ChatParseError` |
| `chatRequest.ts` | `parseChatPrompt()`：请求体 → 提示与参数；system/developer 归并、user 分段（text/image_url）、assistant `tool_calls` → tool-call part、`role:'tool'` → tool-result（toolName 由前置 assistant 调用补全）；`max_completion_tokens`/`max_tokens` → `maxOutputTokens`；`stop` → `stopSequences`；不合规结构抛 `ChatParseError` → 400 |
| `upstream.ts` | `planUpstream()`：按协议构造模型实例 + provider 专属参数计划；Anthropic thinking 预算映射（low 1024 / medium 4096 / high 10000，启用时禁用采样参数并保证 `max_tokens` > 预算）；`ensureVersioned()` baseUrl 规范化 |
| `chatResponse.ts` | `createChunkWriter()`：统一流 → SSE 块写出器（惰性响应头）；`sendChatCompletion()`：非流式聚合响应；finish_reason / usage 映射 |
| `convertHandler.ts` | `forwardConverted()`：主流程、abort 传递、上游错误映射（`APICallError.statusCode` → 状态码，其余 502）、日志落库 |

## 线上格式约定

- **流式**：`chat.completion.chunk`；首块 `delta:{role:'assistant',content:''}`；`text-delta→content`、`reasoning-delta→reasoning_content`（DeepSeek 约定字段，主流客户端可读）；工具调用优先按 `tool-input-start/delta` 增量下发 `delta.tool_calls[].function.arguments`（id→index 映射），上游未给增量时整段下发完整 `tool-call`；`finish_reason` 块后补独立 usage 块（`choices:[]`，等价 OpenAI `include_usage`）+ `data: [DONE]`
- **流内错误**：响应头未写出前发现错误 → 直接以真实状态码返回 JSON 错误信封；已开始流式后出错 → `data:{"error":{…}}` + `[DONE]`
- **非流式**：`chat.completion`，`message.reasoning_content` / `message.tool_calls` 按需出现
- **abort**：客户端断开 → `abortSignal` 中止上游，日志记 status 499、不计用量

## baseUrl 规范化（`ensureVersioned`）

转换路径下 ai-sdk 的 baseURL 需以 `/v1` 结尾（SDK 自行追加 `/messages`、`/responses` 末段）。规则：去尾斜杠后若不匹配 `/\/v\d+$/` 则补 `/v1`。因此 `https://api.anthropic.com`、`https://open.bigmodel.cn/api/anthropic` 等均可直接使用。**`openai` 类透传路径不规范化**（维持原样拼接语义）。

## 已知限制（转换路径）

- 仅支持 `n=1`（>1 返回 400）
- 忽略 OpenAI 专属参数：`response_format` / `logprobs` / `prediction` / `stream_options` 等（透传路径不受影响）
- `reasoning_effort`：`minimal` 不启用 thinking；`low/medium/high` 映射 Anthropic thinking 预算或透传 Responses `reasoningEffort`
- Anthropic 上游强制 `max_tokens`：客户端未传时默认 4096
- 不透传客户端自定义请求头（认证头由 SDK 按 upstream 协议重建）

## 与日志的关系

日志表结构与 UI 本期未改。转换路径的 `usage` 取自 ai-sdk 统一 `LanguageModelUsage`（`inputTokens/outputTokens/totalTokens` → `prompt_tokens/completion_tokens/total_tokens`），经 `proxyLog.ts` 复用同一落库管线。
