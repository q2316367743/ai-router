# 余量查询（策略模式）

> 2026-09-19。查询编程套餐的剩余额度（5 小时 / 周 / 月窗口、余额、明细）。策略模式：
> **内置策略** = 代码内置方法（移植自 CodexBar Swift 工程，不可卸载不可删除）；**外置策略** = 用户 JS 脚本（`defineProvider` 契约，eval 加载，可卸载可删除）。两者统一注册进内存 Map，提供商通过 `providers.quotaStrategyId` 绑定任意一条策略。

## 架构

```
providers.quotaStrategyId ──→ registry: Map<id, { meta, fetch }>
                                   ├─ 内置：native TS 策略（quota/builtin/native/*.ts）
                                   ├─ 内置：脚本策略（CodexBar 插件原样复用，quota/builtin/builtin-plugins/*.js）
                                   └─ 外置：用户脚本（quota_plugins 表，启动/安装时 eval 加载）
```

- 契约：`src/common/types/quota.ts`（`QuotaSnapshot` / `QuotaStrategy` / `QuotaStrategyMeta` / `ProviderQuotaInfo` 等，三端共享）。
- 注册表：`src/main/src/quota/registry.ts`。内置注册冲突抛错；`unregisterStrategy` 对内置条目是 no-op（不可卸载）。
- 装配：`quota/scheduler.ts` 的 `startQuotaScheduler()`——注册内置 → 装载外置 → 启动 5s 首刷 + `setInterval` 10 分钟（照抄 tray.ts 模式，try/catch 静默）。在 `main/index.ts` whenReady 链 `startProxyServer()` 之后调用。
- 刷新：`quota/service.ts` 的 `refreshProviderQuota(providerId?)`——取 `enabled && 未归档 && 已绑定策略` 的提供商，逐家执行 `strategy.fetch(ctx)`，成功 `normalizeSnapshot` 落库、失败写 `error`（**保留旧快照**，UI 展示旧值 + 失败原因）。
- 快照表：`quota_snapshots`（每提供商一行 UPSERT），页面 `quota:list` 只读库不出站；`quota:refresh` 才出站。
- **可观测性**：整条链路以 `[quota]` 前缀打日志——调度器启动（策略条数汇总）、本轮无目标（说明绑定/停用/归档状态）、每家成功/失败（含策略名与耗时）、失败原因（HTTP 状态 / 超时 / 凭证问题）；启动失败只记错不抛，不拖垮 whenReady 链。native 策略与脚本策略统一有 20s 整体超时（`withTimeout`，超时报「XX 余量查询 超时（20s）」）。

## 外置策略（用户脚本）

- 存储：`quota_plugins` 表（`script` 列存脚本全文），`quotaPlugin:list/create/update/archive` 管理；创建/更新前 main 侧 `validatePluginScript()` 先 eval 校验（失败中文报错不落库），成功后 `reloadExternalStrategies()` 重载注册表。
- 归档（假删除）：单事务连带 `providers.quotaStrategyId = null`（解绑）+ 注册表 `unregister`。
- 脚本契约（`defineProvider`，完整类型参考 `quota/runtime/codexbar-plugin.d.ts`）：

```js
defineProvider({
  id: 'my-plugin',
  name: 'My Plugin',
  endpoints: ['https://example.com'],                      // origin 白名单，脚本请求出界被拒
  auth: { type: 'bearer', secret: 'MY_KEY' },              // 认证头宿主附加，脚本不可覆盖
  settings: [{ key: 'MY_KEY', title: 'API Key', type: 'secure' }],
  async fetchUsage(ctx) {
    const res = await ctx.http.getJSON('https://example.com/usage')
    if (res.status !== 200) throw ctx.fail.apiFailure(`HTTP ${res.status}`)
    return {
      primary: { usedPercent: res.json.percent, windowMinutes: 300,
                 resetsAt: Date.now() + res.json.resetInSec * 1000, resetDescription: '5 小时' },
      details: [{ title: '明细', rows: [{ label: '已用', value: '123' }] }]
    }
  }
})
```

## 脚本运行时（`quota/runtime/`）

复刻 CodexBar ProviderPluginRuntime（宿主桥为 Node 实现）：

- `evaluate.ts`：`(0, eval)(prelude)` 求值便捷层注入函数 + `new Function('defineProvider', src)` 捕获 definition；加载期提取 manifest（settings/auth/capabilities/cookieDomains/endpoints 白名单）并做最低形状校验。
- `hostBridge.ts`：`host.http` 包装 `getUpstreamClient()`（复用 `server.proxyUrl` 出站代理与网络错误增强；`timeoutSeconds` 1~30 默认 15；响应体上限 5MB；认证头按 manifest.auth 附加）；`settingGet`（未声明键拒绝读取）、`cookieHeader`（域须在 `cookieDomains` 内，值取提供商附加配置 `cookie`）、进程内 cache、log（secrets 脱敏）、`pct`、`nextDailyReset`（跨时区日界）。
- `context.ts`：每次 fetch 构造新 ctx（`__codexbarNowMillis` 注入时钟）→ prelude 注入 `ctx.http/settings/date/fail/format/cache/jwt/log/pct` → `fetchUsage(ctx)` 整体 20s 超时（超时放弃该次结果，Node 无法中断脚本）→ `normalizeSnapshot`（窗口字段收敛：`resetsAt` 兼容 Date/秒/毫秒/ISO；至少含一项有意义数据）。内置 TS 策略用 `makeNativeContext` 走同一宿主桥（无白名单）。
- `failure.ts`：`ctx.fail.*` 抛 `__CODEXBAR_FAILURE_V2__:<kind>::<message>`，宿主解析 8 种 kind 映射中文文案（凭证过期 / 缺凭证 / 限流 / 解析失败等），展示在快照 `error` 与余量页 alert。

## 坑与约束

- **eval 无沙箱**：脚本能访问 Node 全局，这是本地应用执行用户自带脚本的已知取舍（宿主只做 origin 白名单 + auth 附加 + 设置键声明约束；间接 eval 避免闭包泄漏）。
- **整行回传 update 必须带全 `kind`/`quotaStrategyId`/`strategyConfig`**：repo 对三者都是显式写（`?? null`），providers 页行内启停已带上，新增调用点照抄。
- **外置策略归档连带解绑**提供商（事务），余额快照不删；失败时快照保留旧值只更新 error。
- Codex 令牌不自动刷新：过期后 UI 提示重新 `codex login` 或更新附加配置；Cookie 类策略同理会过期。
- `quota:list` 是纯读库路径（可高频安全调用）；出站刷新只在 `quota:refresh` 与调度器发生。
- `src/main/src/env.d.ts` 声明 `*.js?raw` 模块类型（vite 构建期内联为字符串，无运行时文件读取）。
