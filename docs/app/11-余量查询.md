# 余量查询（策略模式）

> 2026-09-19。查询编程套餐的剩余额度（5 小时 / 周 / 月窗口、余额、明细）。策略模式：
> **内置策略** = 代码内置方法（移植自 CodexBar Swift 工程，不可卸载不可删除）；**外置策略** = 用户 JS 脚本（`defineProvider` 契约，eval 加载，可卸载可删除）。两者统一注册进内存 Map，提供商通过 `providers.quotaStrategyId` 绑定任意一条策略。
>
> **2026-09-20 内置脚本策略已全量迁为 native TS（35/35）**：`scripted.ts` 与 `builtin-plugins/` 已删除，`quota/builtin/` 只剩 `index.ts + util.ts + native/`。动机：本项目与 CodexBar 无上游同步关系，脚本形态只剩类型零覆盖与双范式成本（详见 git history 与下文「脚本迁移」节）。eval 运行时（prelude/origin 白名单/failure 映射）**保留服务外置用户插件**，一个字未删。新内置策略一律直接写 native TS。

## 架构

```
providers.quotaStrategyId ──→ registry: Map<id, { meta, fetch }>
                                   ├─ 内置：native TS 策略 ×35（quota/builtin/native/*.ts）
                                   └─ 外置：用户脚本（quota_plugins 表，启动/安装时 eval 加载）
```

- 契约：`src/common/types/quota.ts`（`QuotaSnapshot` / `QuotaStrategy` / `QuotaStrategyMeta` / `ProviderQuotaInfo` 等，三端共享）。
- 注册表：`src/main/src/quota/registry.ts`。内置注册冲突抛错；`unregisterStrategy` 对内置条目是 no-op（不可卸载）。
- 装配：`quota/service.ts` 的 `initQuota()`——注册内置 → 装载外置 → 预热脚本宿主（try/catch 静默，失败不拖垮启动链）。在 `main/index.ts` whenReady 链 `startProxyServer()` 之后调用。**刷新节奏拆到 scheduler（2026-09-23）**：原 `quota/scheduler.ts` 已删除，启动 5s 首刷 + 每 10 分钟一轮由 `scheduler` 域的 `quota:refresh` 任务驱动（见 `13-定时任务.md`）。
- 刷新：`quota/service.ts` 的 `refreshProviderQuota(providerId?)`——取 `enabled && 未归档 && 已绑定策略` 的提供商，逐家执行 `strategy.fetch(ctx)`，成功 `normalizeSnapshot` 落库、失败写 `error`（**保留旧快照**，UI 展示旧值 + 失败原因）。
- 快照表：`quota_snapshots`（每提供商一行 UPSERT），页面 `quota:list` 只读库不出站；`quota:refresh` 才出站。
- **可观测性**：整条链路以 `[quota]` 前缀打日志——调度器启动（策略条数汇总）、本轮无目标（说明绑定/停用/归档状态）、每家成功/失败（含策略名与耗时）、失败原因（HTTP 状态 / 超时 / 凭证问题）；启动失败只记错不抛，不拖垮 whenReady 链。native 策略与脚本策略统一有 20s 整体超时（`withTimeout`，超时报「XX 余量查询 超时（20s）」）。

**脚本迁移映射规则**（脚本宿主行为 → native 等价写法，迁移时统一套用）：

- `ctx.settings.get/getSecret('K')` → `strOf(ctx.config.K)`（trim + 空转 null 语义等价；native 桥的 settingGet 对未配置的声明键会抛错，与脚本「manifest 声明即许可」语义不同，故 native 禁用 settings 通道）
- manifest.auth 宿主自动附加认证头 → 策略手动构造（bearer / x-api-key / authorization-scheme；空值时不附加，与 hostBridge 一致）
- `ctx.browser.cookieHeader(domain)` → `strOf(ctx.config.cookie)`，未配置抛 `ctx.fail.missingCredential('请在提供商的附加配置中粘贴 <domain> 的 Cookie 头')`，拿到后手动加 `Cookie` 头（native 桥 cookieDomains 为空必拒；域校验属不可信代码防护栏，内置可信代码直读配置）
- 宿主 `normalizeSnapshot` 会丢弃的返回字段（`costUsage`/`dataConfidence`/`nextRegenPercent`/`nextRegenAmount` 等）不移植，其「有无数据」判定改用局部变量
- `ctx.date.unixSeconds/unixMillis` 返回 Date → 快照字段直接写 epoch 毫秒数值（normalizeWindow 归一同值）

**迁移中的有意修正**（非 1:1，已逐条确认）：

- `openrouter`：activity 认证真正接上 `OPENROUTER_MANAGEMENT_API_KEY`（脚本宿主桥本就忽略 `openRouterManagementAuth` 标记、恒发主 Key，属缺陷修正）；`X-Title` 缺省 `CodexBar` → `ai-router`
- `huggingface`：身份缓存从 `ctx.cache`（宿主 `String()` 序列化会把对象退化为 `"[object Object]"`，脚本路径实为缺陷）改为模块级 Map，保留 12 小时 TTL 本意
- 脚本路径特有的双层 20s 超时（fetchByPlugin 内层 + service 外层）收敛为 service 层单层

**批次 2（待实现）**：C 类 Cookie 手贴家（Alibaba/Abacus/Amp/Augment/Cursor/Factory/Grok/Groq/LongCat/MiMo/Mistral/Notion/Ollama/OpenCode-web/QwenCloud/Sakana/Windsurf/ZoomMate 等）、B 类 OAuth（Claude/Copilot/Gemini/VertexAI/Antigravity/StepFun）、D 类本地（Bedrock SigV4/JetBrains XML/Zed Keychain/Wayfinder/Kiro/CodeRabbit CLI）、Doubao（火山 V4 签名）、IBMBob/Kilo/Fireworks（响应结构待逐家确认）。

## 外置策略（用户脚本）

- 存储：`quota_plugins` 表（`script` 列存脚本全文），`quotaPlugin:list/create/update/archive` 管理；创建/更新前 main 侧 `validatePluginScript()` 先 eval 校验（失败中文报错不落库），成功后 `reloadExternalStrategies()` 重载注册表。
- 归档（假删除）：单事务连带 `providers.quotaStrategyId = null`（解绑）+ 注册表 `unregister`。
- 脚本契约（`defineProvider`，完整类型参考 `quota/runtime/codexbar-plugin.d.ts`）：

```js
defineProvider({
  id: 'my-plugin',
  name: 'My Plugin',
  endpoints: ['https://example.com'],                      // origin 白名单，脚本请求出界被拒
  auth: { type: 'bearer', secret: 'MY_KEY' },              // 认证头宿主附加，脚本不可覆盖
  settings: [{ key: 'MY_KEY', title: 'API Key', type: 'secure' }],
  async fetchUsage(ctx) {
    const res = await ctx.http.getJSON('https://example.com/usage')
    if (res.status !== 200) throw ctx.fail.apiFailure(`HTTP ${res.status}`)
    return {
      primary: { usedPercent: res.json.percent, windowMinutes: 300,
                 resetsAt: Date.now() + res.json.resetInSec * 1000, resetDescription: '5 小时' },
      details: [{ title: '明细', rows: [{ label: '已用', value: '123' }] }]
    }
  }
})
```

## 脚本运行时（`quota/runtime/`）

复刻 CodexBar ProviderPluginRuntime（宿主桥为 Node 实现）：

- `evaluate.ts`：`(0, eval)(prelude)` 求值便捷层注入函数 + `new Function('defineProvider', src)` 捕获 definition；加载期提取 manifest（settings/auth/capabilities/cookieDomains/endpoints 白名单）并做最低形状校验。
- `hostBridge.ts`：`host.http` 包装 `getUpstreamClient()`（复用 `server.proxyUrl` 出站代理与网络错误增强；`timeoutSeconds` 1~30 默认 15；响应体上限 5MB；认证头按 manifest.auth 附加）；`settingGet`（未声明键拒绝读取）、`cookieHeader`（域须在 `cookieDomains` 内，值取提供商附加配置 `cookie`）、进程内 cache、log（secrets 脱敏）、`pct`、`nextDailyReset`（跨时区日界）。
- `context.ts`：每次 fetch 构造新 ctx（`__codexbarNowMillis` 注入时钟）→ prelude 注入 `ctx.http/settings/date/fail/format/cache/jwt/log/pct` → `fetchUsage(ctx)` 整体 20s 超时（超时放弃该次结果，Node 无法中断脚本）→ `normalizeSnapshot`（窗口字段收敛：`resetsAt` 兼容 Date/秒/毫秒/ISO；至少含一项有意义数据）。内置 TS 策略用 `makeNativeContext` 走同一宿主桥 + 同一 prelude（无白名单、无 manifest auth 宿主附加，认证头需策略自加）；`QuotaStrategyContext` 已声明 date/format/isDetailLabel/settings.getSecret（两侧运行时同构）。
- `failure.ts`：`ctx.fail.*` 抛 `__CODEXBAR_FAILURE_V2__:<kind>::<message>`，宿主解析 8 种 kind 映射中文文案（凭证过期 / 缺凭证 / 限流 / 解析失败等），展示在快照 `error` 与余量页 alert。

## 下游消费：负载均衡的额度前置拦截（2026-09-23）

快照从「只用于展示」变成**路由决策的输入**：`quota/service.ts` 每轮刷新落库后调
`balancer.applyProviderQuota(providerId, snapshot)`（启动时 `syncQuotaBlocks()` 用落库快照重建），
任一窗口 `usedPercent >= 100`（且未到 `resetsAt`）或 `cost.balance <= 0` → 该提供商可用度直接归零、
不再分到任何流量；`resetsAt` 到点由 `health.availabilityOf` 惰性解除（不必等下一轮刷新）。
判定细节、解除时机与全阻断时的 503 见 `15-负载均衡与故障转移.md`。

注意两点：

- **刷新失败不解除已有阻断**（`snapshot` 为 null 时 `applyProviderQuota` 直接返回）：无信息不等于健康。
- 没绑策略的提供商没有快照，只能靠响应侧推断（402 / 429 带额度关键字 → 阻断 10 分钟）。

## 坑与约束

- **eval 无沙箱**：脚本能访问 Node 全局，这是本地应用执行用户自带脚本的已知取舍（宿主只做 origin 白名单 + auth 附加 + 设置键声明约束；间接 eval 避免闭包泄漏）。
- **整行回传 update 必须带全 `kind`/`quotaStrategyId`/`strategyConfig`**：repo 对三者都是显式写（`?? null`），providers 页行内启停已带上，新增调用点照抄。
- **外置策略归档连带解绑**提供商（事务），余额快照不删；失败时快照保留旧值只更新 error。
- Codex 令牌不自动刷新：过期后 UI 提示重新 `codex login` 或更新附加配置；Cookie 类策略同理会过期。
- `quota:list` 是纯读库路径（可高频安全调用）；出站刷新只在 `quota:refresh` 与调度器发生。
- `src/main/src/env.d.ts` 声明 `*.js?raw` 模块类型（vite 构建期内联为字符串，无运行时文件读取）。
