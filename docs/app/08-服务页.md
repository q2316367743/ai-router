# 08 - 服务页

> 服务页重构（2026-09-19）：从三张 `t-card` 设置卡改为「连接凭据优先」的 Fluent 布局，并把接入示例按三个协议入口分栏。仅渲染层改动，ServiceConfig / ServiceStatus 契约与 IPC 均不变。

## 实现思路

旧版按「服务配置 / 对接信息 / 接入示例」三张 `t-card header-bordered` 纵向堆叠，问题：

- 最高频动作（复制 Base URL / API Key 去配客户端）被埋在中间卡的小号 `<code>` 文本里，复制按钮小且端点是纯图标按钮；
- 接入示例只覆盖 OpenAI 兼容（curl / Codex / 通用 Agent 三 tab 分类混乱：协议名与客户端名混用），`/v1/messages`、`/v1/responses` 两个入口在页面上完全不可发现；
- Anthropic 系客户端 Base URL 不应带 `/v1`（SDK 会自动拼 `/v1/messages`），旧页「Base URL 填此项」的指引对这类客户端是错的。

新版围绕接入动线重组为两张卡：

1. **连接卡**（`index.vue`）：状态行（呼吸光点 + 状态 + 总开关）→ Base URL → API Key → 监听端口，四个 field-row 用发丝线分隔；Base URL / Key 用只读 `t-input` + 外置图标按钮（方形 outline），Key 增加显隐切换与重新生成（popconfirm）。
2. **接入示例卡**（`ServiceAccessExamples.vue`）：`t-radio-group variant="default-filled"` 分段控件（与设置页外观切换同款）在三个协议入口间切换，每栏含：`POST` 方法章 + 端点路径、该协议实际应填的 Base URL（可复制）、数据驱动的代码片段组（每段独立复制按钮 + 可选 note）。

## 关键文件

| 文件 | 职责 |
| --- | --- |
| `src/renderer/src/windows/main/pages/service/index.vue` | 连接卡 + 状态行；`statusMeta` 四态派生（running / error / wait / off） |
| `src/renderer/src/windows/main/pages/service/components/ServiceAccessExamples.vue` | 三协议示例；`ProtocolTab[]` 数据驱动渲染 |
| `src/renderer/src/utils/clipboard.ts` | 共享 `copyText`（写剪贴板 + 统一 MessageUtil 提示），页面与示例组件共用 |

## 数据结构 / 契约

- 契约不变：`@common/types/service.ts` 的 `ServiceConfig` / `ServiceStatus`，链路仍是 `window.preload.service.{getConfig,getStatus,saveConfig,regenerateKey,onStatusChanged}`。
- 新增组件内部接口 `ProtocolTab { value, label, path, baseUrl, baseUrlNote, snippets[] }`，`snippets` 由 `endpoint`（`http://127.0.0.1:<port>/v1`）与 `apiKey` 实时卷入，生成后无需手动同步。
- 三个协议栏与 `main/src/server/app.ts` 的三条入口路由一一对应：`/v1/chat/completions`、`/v1/messages`、`/v1/responses`（另提示 `GET /v1/models`）。

## 注意事项

- **Base URL 按协议分栏展示**：OpenAI 系（Chat / Responses）带 `/v1`；Anthropic 栏用 `endpoint.replace(/\/v1$/, '')` 还原根地址。Claude Code 片段用 `ANTHROPIC_AUTH_TOKEN`（走 `Authorization: Bearer`，服务端支持），curl 片段演示 `x-api-key`（同样支持）。
- Codex 片段改为 `wire_api = "responses"`（旧示例是 `"chat"`），因为 `/v1/responses` 入口现已开放，Codex 可走原生 Responses 协议；env_key 对应环境变量在 snippet note 中说明。
- 状态点颜色显式取色阶而非语义色：浅色取暗端（success-5 / error-5 / warning-6），`theme-mode='dark'` 下经 CSS 变量 `--dot-color` 覆盖为亮端（success-8 / error-7 / warning-8），与 `customer.less` 的 stat-* 分档同理。
- 运行态呼吸光环只动 `transform` / `opacity`（2.4s ease-out），符合 Fluent 轻动效约束。
- 已知取舍：示例代码片段内嵌真实 API Key（含明文），便于复制即用；Key 本就展示在本页，无额外泄露面。
