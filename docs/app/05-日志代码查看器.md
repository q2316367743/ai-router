# 日志代码查看器（Monaco）

> 2026-09-16：日志页行展开详情中的请求/响应正文与错误信息改用 Monaco 渲染，替换原先的 `v-html` 高亮与 `<pre>` 直出，解决大文本卡顿，并补充搜索/折叠/复制能力。

## 背景与目标

原实现（`JsonView.vue` + `LogPayloadPanel.vue` 的 `raw-block`）在正文较大时明显卡顿，根因两条：

1. `JSON.parse → JSON.stringify(…, null, 2) → 正则高亮 → v-html`：一次性生成巨型 HTML，`innerHTML` 解析 + 布局成本随文本线性膨胀。
2. 文本容器使用 `white-space: pre-wrap` + `word-break: break-all`：超长文本的逐字符断行是浏览器最慢的排版路径；流式响应的 SSE 正文可达 MB 级。

Monaco 按视口按行虚拟渲染，只处理可见行，从根本上消除上述两项开销，同时自带查找/折叠/复制。

## 实现要点

### 动态加载（不进首屏 / 托盘窗口）

`CodeViewer` 在 `onMounted` / 首次有内容时才 `await import()` Monaco，日志页虽为懒加载路由，这样可进一步保证「只看列表不展开」时不下载 Monaco；托盘窗口（`tray.html`）完全不受影响。`monacoApi` 在模块级缓存，第二次创建编辑器不再重复 import。

### 入口选择与 subpath（重要，两个坑）

**坑 1：不能用 `editor.api` 作为运行时入口。** Monaco 0.56 的 `editor.api` 是**纯 API 入口，不包含任何 contributions**，而核心编辑器依赖由 contribution 注册的服务（如 `actionWidgetService`），用它创建实例会抛：

```
Uncaught Error: [createInstance] _a7 depends on UNKNOWN service actionWidgetService.
```

必须用包含全部 contributions 的入口——即 root `monaco-editor`（`esm/vs/index.js`，也等同于 `editor.main`）：

```ts
import * as monaco from 'monaco-editor' // 运行时
```

代价是连带引入全部语言定义与 css/html/json/typescript 语言服务；因日志页懒加载且仅在展开时才动态 import，可接受。0.56 已无 `editor.all.js` 这种「contributions only」入口，无法只取 contributions 而排除语言。

**坑 2：`exports` 映射使旧 deep import 路径失效。** 0.56 `package.json` 为 `"./*": "./esm/vs/*.js"`，故 `monaco-editor/esm/vs/editor/editor.api` 会被解析成不存在的 `esm/vs/esm/vs/...`。省略 `esm/vs` 前缀才是正确路径（worker 仍走此形式）：

```ts
import EditorWorker from 'monaco-editor/editor/editor.worker?worker'
import JsonWorker from 'monaco-editor/language/json/json.worker?worker'
```

类型仍可从 `monaco-editor`（`index.d.ts` 重导出 `editor.api` 的全部类型）获取，无需额外 ambient 声明。

### Web Worker 配置

```ts
self.MonacoEnvironment = {
  getWorker: (_workerId, label) => (label === 'json' ? new JsonWorker() : new EditorWorker())
}
```

`self.MonacoEnvironment` 的全局声明由 `editor.api.d.ts` 提供，无需自行 `declare global`。worker 通过 Vite `?worker` 动态导入，独立 chunk 加载。若在 Electron `file://` 下出现 worker 加载失败，改用 `?worker&inline` 兜底（以 base64 内联，牺牲体积换稳定）。

### 主题（tdesign token）

`buildTheme()` 运行时从 `document.documentElement` 读取 tdesign 语义色并构造 Monaco 主题 `ai-router-log`：

- 背景/前景/行号/当前行高亮 ← `--td-bg-color-container` / `--td-text-color-primary` / `--td-text-color-placeholder` / `--td-bg-color-container-hover`
- JSON token 色对齐原自研高亮：key→brand、字符串→success、数字→warning、关键字→error

**颜色格式（易踩坑）**：`colors` 与 `rules[].foreground` 的格式要求**相反**——

- `colors.*` 经 `Color.fromHex(value)` 解析，**必须带 `#`**；非法值会被静默回退成 `Color.red`，表现为**整个编辑器红色背景**（见 `node_modules/monaco-editor/esm/vs/base/common/color.js:182`）。故用 `hexColor()` 在非 `#hex` 时退回默认值。
- `rules[].foreground` **不能带 `#`**（`tokenization.js:127` 内部会补 `#`），故用 `tokenColor()` 去掉前缀。

`base` 取 `vs` / `vs-dark`，`inherit: true`。监听 `useColorMode().isDark`，切换时 `defineTheme` + `setTheme`。

### 空值与高度

- `value` 为空：不创建编辑器，展示「（空）」占位。
- `height` 为字符串，父容器需给高度（页面内用 `100%` 填满固定高面板，错误块用 `200px`）。
- 开启 `automaticLayout`，容器尺寸变化自动重排。

### 多实例与刷新

Monaco 单实例内存开销较大：行折叠时 `LogExpandedRow` 卸载，`onBeforeUnmount` 调 `editor.dispose()`。列表 30s 轮询下，同 `row-key` 的行组件被复用，不会重建已展开编辑器。

## 注意事项

- 超长文本阈值 `MAX_PRETTY_LENGTH = 512 * 1024`：超过则跳过 `JSON.parse/stringify`（该步骤本身占主线程），按纯文本渲染。
- `package.json` 中 `monaco-editor` 归入 `devDependencies`（与 echarts/tdesign 一致，由渲染层 Vite 打包，不进 main/preload 的 externalize 流程）。
- 组件当前为日志页私有（`pages/logs/components/`）；若后续其他页面复用，再提升到 `src/renderer/src/components/`。
