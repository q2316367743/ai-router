# 09 - 看板卡片规范

> 2026-09-16。首页与托盘面板共用的看板卡片统一为**四段解剖**：
> 头部（图标 + 标签 + 状态胶囊）/ 大数值 + 小单位 / 卡内迷你可视化 / 页脚明细。
> 参考 CatStatus 的卡片语言，解决此前「所有卡片同一权重、信息层级扁平」的问题。
> 只换视觉与信息层级，卡片数量与指标口径不变；顺带补上了托盘面板缺失的服务状态显示。

## 实现思路

- **原语只管解剖，不管语义**：`MetricCard` 只提供四段结构与间距，分档色、胶囊文案、迷你图数据
  全部由调用方决定，卡片组件不判断业务好坏。
- **配置与渲染分离**：四张统计卡的「图标 / 胶囊 / 迷你图 / 页脚」在 `useUsageCards` 里派生成
  `UsageCardConfig[]`，模板只遍历渲染 —— 新增指标时改一个配置项即可，不用改模板。
- **卡片底色反转**：原先是「卡片比容器暗一档」（secondarycontainer），视觉上是「往下沉」；
  参考图的卡片比面板底**更亮**（container 白底 + 阴影），这才是「浮起」。改完层级立刻分明。
- **只用真实数据画图**：迷你图只画有数据支撑的形状，绝不为「每张卡都有图」而编造可视化。

## 卡片解剖（`MetricCard`）

```
┌──────────────────────────────────────┐
│ [icon] 标签文字   [?]     [状态胶囊]  │  13px/500 次要色
│                                      │
│  1,248  次                           │  t-statistic：26px/600 + 11px 单位
│                                      │
│  ▁▃▂▅▄▂▁   /   ▓▓▓▓▓░░░              │  迷你可视化 28px / 6px
│                                      │
│ 页脚明细 11px placeholder             │
└──────────────────────────────────────┘
```

| props                    | 说明                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `label`                  | 头部标签文字（必填）                                                  |
| `icon`                   | tdesign 图标名，不手写 SVG                                            |
| `pillText` / `pillTheme` | 状态胶囊；不传则不渲染                                                |
| `hint`                   | 口径说明，渲染为标题旁的问号 tooltip                                  |
| `footer`                 | 页脚明细，11px placeholder                                            |
| `valueSize`              | 数值字号，经 `--metric-value-size` 下传（默认 26，托盘紧凑模式传 22） |

| 插槽     | 用途                                                                        |
| -------- | --------------------------------------------------------------------------- |
| 默认     | 数值区（通常放 `t-statistic`）                                              |
| `viz`    | 卡内迷你可视化；`v-if` 加在具名插槽上，无可视化时整段不注册、卡片不多出空白 |
| `footer` | 页脚插槽，优先于 `footer` 文案（当前未使用，留给需要富文本页脚的场景）      |

间距与字号：卡片内边距 `14px 16px`、圆角 `--fluent-radius-card`(14px)、卡片间距 10px、
数值 26px（紧凑 22px）、单位 11px、标签 13px、页脚 11px，数字一律 `tabular-nums`。

### 上下对齐（2026-09-19）

四卡被 `grid-cols-4` 等高拉伸后，卡内内容**自上而下堆叠会让矮内容卡的卡底留白参差**
——迷你柱 28px、迷你进度条只有 6px，成功率/平均延迟两卡的页脚比左右高约 22px。

规则：`.metric-card` 是纵向 flex，`.metric-value` 挂 `margin-top: auto` —— 头部钉顶，
「数值 + 可视化 + 页脚」整体沉底。四卡页脚下缘对齐、标题上缘对齐，中段留白归中间。
其余 MetricCard 使用方（图表卡/活跃度卡/构成/占比卡）都是自然高度、不被 grid 拉伸，
`margin-top: auto` 对它们无副作用，故规则写在原语上而不是统计卡里。

## 层级手段（改动前后）

| 手段         | 改前                                                   | 改后                                                                                              |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 卡片底色     | `--td-bg-color-secondarycontainer`（比容器暗，往下沉） | `--td-bg-color-container`（白底，往上浮）+ `--fluent-card-shadow`                                 |
| 数值         | 22px 手写 div，无单位层级                              | `t-statistic` 26px/600 数值 + 11px 次要色单位                                                     |
| 头部         | 纯文字标签                                             | tdesign 图标 + `t-tag` 状态胶囊（`variant="light" size="small" shape="round"`，再收紧到 20px 高） |
| 卡内可视化   | 无（只有左侧 3px 色条，已移除）                        | 迷你柱图 / 迷你进度条                                                                             |
| 覆盖样式位置 | 分散在各卡片的 scoped 样式里                           | 统一进 `tdesign-cover.less`（`t-statistic` / 胶囊）与 `customer.less`（分档色与渐晕）             |

分档渐晕用 CSS 变量传递而非每个档位写一遍背景规则：`customer.less` 里每档同时声明
`color` 与 `--metric-tint`，卡片只写一条 `background-image: radial-gradient(... var(--metric-tint))`。
纯文字场景（首页状态行）只吃到 `color`，不会被铺上渐晕。
渐晕取的是不透明色阶，故经 `--metric-tint-alpha`（默认 100%）在 `color-mix` 里降透明度后才铺上：
不透明底色下与原来一致，半透明卡片场景调低（托盘面板给 60%），否则卡片角落会糊出一块实色。

### 卡片底的 token 化（2026-09-17）

卡片底从 `--td-bg-color-container` 改为 `--fluent-card-bg`（缺省回退内容容器）。缺省值
（浅 `rgba(255,255,255,0.7)` / 暗 `rgba(32,31,30,0.7)`）在不透明容器上合成结果与原色**一致**
（0.7 白叠 #ffffff、0.7 的 #201f1e 叠 #201f1e），所以首页观感没变；意义是**窗口可以整体重定向
这个 token**：托盘面板把它指向 `--fluent-acrylic-card-bg`，卡片就成了亚克力面上的玻璃卡片
（详见 `03-托盘.md`）。层级关系不变 —— 卡片始终比面板底更亮/更实，靠 alpha 差 + 描边 + 阴影表达浮起。

### 顶部分段控件（2026-09-17 修订）

看板顶部的维度切换（今天 / 近 24 小时 / 近七天 / 近 30 天）从 `variant="outline"` 换成
`variant="default-filled"`，并挂上新原语 `.fluent-segmented`（`tdesign-cover.less` 的 Fluent 特有组件族）。

**为什么换**：outline 变体的按钮是「不透明底 + 硬边框」（`.t-radio-group__outline .t-radio-button`
带 1px `--td-border-level-2-color` 边框与首尾圆角拼接），在托盘亚克力面板上是唯一的实色块，
且圆角（`--td-radius-default` 6px）与尺寸节奏跟卡片语言不搭。

| 部件          | 原值                                                    | 现值                                                                          |
| ------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 轨道底        | `--td-bg-color-component`（不透明灰）                   | `color-mix(in srgb, var(--td-gray-color-14) 8%, transparent)`（半透明暗色洗） |
| 选中缩略块    | `--td-bg-color-container-select`（实白 / 暗 #605e5c）   | `--fluent-card-bg`（托盘里即玻璃卡片底）+ inset ring + `--fluent-elevation-1` |
| 段间 1px 竖线 | `.t-radio-button::before` 显式绘制                      | 隐藏（窄控件里是噪音，Fluent 分段控件不画）                                   |
| 圆角          | 轨道 `--td-radius-default` / 缩略块 `--td-radius-small` | `--fluent-radius-smooth` / 该值减 2px                                         |

要点：

- **滑动是组件自带的，不用自己写**：filled 变体渲染 `.t-radio-group__bg-block`，TDesign 按选中项算
  `left` / `width` 并带过渡；改成 `flex: 1` 等宽后它照样跟随，无需索引 CSS 变量或缩略块元素。
- **层级语义与卡片一致**：轨道比底**暗**、缩略块比底**亮**（底 + 描边 + 阴影），控件仍比所在底更实，
  只是不再是不透明块。
- **描边必须用 inset 阴影而不是 `border`**：缩略块宽度由 TDesign 按选中项 `offsetWidth` 算出，
  实边框会改盒模型宽度，导致缩略块与文字错位。
- 文字色沿用 TDesign 自带（未选中次要色 / 选中主色 + 悬停转主色），覆盖里不重复声明颜色。
- 托盘紧凑模式额外挂 `.fluent-segmented--block`：四段等宽铺满面板宽度，避免左对齐后右侧空一大截。
- **只给看板挂类**：日志页的状态筛选与日志详情面板的正文/标头切换仍是 TDesign 原生 outline 外观，
  要统一只需在这两处补上同一个 class。

### 加载态（2026-09-17）

`UsageDashboard` 的 `t-loading` 加了 `:delay="200"`（快速请求完全不闪）与 `:show-overlay="!compact"`
（托盘紧凑模式只留 spinner，不盖遮罩）。原因见 `03-托盘.md` 的面板外观一节 —— 面板每次弹出都会重新取数，
半透明遮罩盖在亚克力上仍然是一整块「跳一下」。

## 迷你图只用真实数据

| 指标      | 图元           | 数据来源                           | 备注                                         |
| --------- | -------------- | ---------------------------------- | -------------------------------------------- |
| 请求数    | `MiniBars`     | `series.requestCount`              | 逐桶有数据 ✓                                 |
| 总 Tokens | `MiniBars`     | `series.totalTokens`               | ✓                                            |
| 成功率    | `MiniProgress` | 成功率本身                         | ✓                                            |
| 平均延迟  | `MiniProgress` | `latency / 5s`（占差档阈值的比例） | 短而绿 = 快，长而红 = 慢                     |
| 缓存占比  | 不画           | —                                  | 已在 Tokens 卡页脚与令牌构成卡中出现，不重复 |
| —         | ~~折线~~       | 延迟**没有**逐桶数据               | 画了就是假图，所以不画                       |

`MiniBars` / `MiniProgress` 的颜色一律 `currentColor`，由所在卡片继承分档色，组件内不写色值表。
全 0 的柱图全部压平：宁可空着也不画一排假柱子。

## 分档与状态胶囊

阈值判定全部在 `useUsageStats`，胶囊文案在 `useUsageCards`（`SUCCESS_PILL` / `LATENCY_PILL` /
`MAGNITUDE_PILL`），色值在 `customer.less` —— 三者各管一层，改一处不会漂移到另一处。

| 档位 | 成功率 | 延迟 | 量级（请求数 / Tokens） | t-tag theme       |
| ---- | ------ | ---- | ----------------------- | ----------------- |
| 1    | —      | 很快 | 较少                    | default           |
| 2    | 尚可   | 偏慢 | 一般                    | warning / default |
| 3    | 偏低   | 很慢 | 较多                    | danger / primary  |
| 4    | —      | —    | 很多                    | primary           |

`good=优秀(success)`；无数据时不显示胶囊 —— 不做无依据的判断。环形指标卡的成功率复用
`successPill()`，与统计卡共用同一套文案。

### 接入新指标

1. 有阈值语义 → 在 `useUsageStats` 加判定函数；没有就跳过。
2. 在 `useUsageCards` 加一项配置（图标、胶囊、迷你图、页脚）。
3. 需要分档色 → 直接挂已有的 `stat-*` 类，不用写色值。
4. 需要新色 → 文字色按它实际所在的底色核算对比度：正文需 ≥ 4.5:1，
   22px/600 以上的统计数字适用大字号 3:1 门槛。

## 服务状态显示

托盘面板此前**完全不显示服务状态** —— 看不出代理有没有在跑，这是参考图以「设备健康度」开头
而我们没有的最大信息缺口。补齐方式：

- `hooks/useServiceStatus.ts`：取一次初始状态 + 订阅 `service.onStatusChanged`，并做端口兜底；
  `serviceStatusMeta()` 把状态映射成胶囊文案与 t-tag 主题，首页与托盘共用同一份措辞。
- 首页用 `components/service/ServiceStatusBar.vue`：状态胶囊 + 端点 + 右侧插槽
  （插槽里放区间数值与服务设置入口，内容不变）。
- **托盘只在标题栏放一个状态胶囊**（`tray/App.vue`），不显示端点 —— 窄面板里端点占宽且非高频信息，
  需要地址时开主窗口或看首页。
- 纯渲染层：复用已有 `service.getStatus` / `onStatusChanged` 桥，**未新增任何 IPC**。

## 已知限制与注意

- **无数据显示 `—` 而不是 `0`**：零请求下的成功率 / 延迟没有语义，`UsageCardConfig.hasValue`
  控制占位符；此时也不渲染迷你图（「没有请求」与「成功率 0%」不是一回事）。
- **延迟进度条的语义**是「占差档阈值（5s）的比例」，不是延迟本身的大小 —— 数值由同卡
  `t-statistic` 承担，胶囊颜色辅助消歧。
- **令牌构成卡没有状态胶囊**：四段构成没有好坏；它已有 4 行自带标签的明细，再加胶囊是噪音。
- **`t-statistic` 的小数位必须显式传**（`UsageCardConfig.decimalPlaces`）：token 数值已在
  `tokenParts` 收过一位小数，整数就传 0，避免出现 `980.0` 或 `2.4 → 2` 这类格式漂移。
- **行数红线**：`UsageActivityCard` 因换壳会超 300 行，热力矩阵已拆到 `UsageHeatmap.vue`。
