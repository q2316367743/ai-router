# 内置提供商（预设快速填写 + 类型标记）

> 2026-09-19。提供商页两项增强：① 新增/编辑**抽屉**支持选内置提供商**快速填写**（自动带出接口协议与官方 Base URL，用户只补 API Key）；② `providers` 表新增 `kind` **类型列**标记该行是哪个内置提供商——这是为后续**余量查询**预留的分发键（按 kind 路由到各家的额度查询 API），本期只落字段与 UI，不做查询实现。

## kind 字段

- 类型：`ProviderKind = 'zai' | 'opencode' | 'deepseek' | 'siliconflow'`（`src/common/types/provider.ts`，三端共享）。**null = 自定义**，存量行为 null 无需回填。
- 列：`providers.kind`（text 可空），迁移 `resources/drizzle/0005_*.sql`（`ALTER TABLE providers ADD kind text`）。
- 契约：`ProviderInfo.kind: ProviderKind | null`；`ProviderInput.kind?: ProviderKind | null`（缺省按 null 落库）。
- IPC 校验：`providerIpc.ts` 的 `assertProviderInput` 对非空 `kind` 做枚举白名单（`KINDS` 常量）。

## 预设目录（`pages/providers/presets.ts`）

```ts
interface ProviderPreset {
  kind: ProviderKind
  label: string                                   // UI 展示名（标签墙、列表标签、名称带出）
  consoleUrl?: string                             // 获取 API Key 的控制台页（选填，最佳 effort）
  urls: Partial<Record<ProviderProtocol, string>> // 各协议官方端点
}
```

当前四家（端点均有官方文档/社区佐证）：

| kind | label | openai 协议 | anthropic 协议 |

| `zai` | Z.ai | `https://api.z.ai/api/coding/paas/v4`（Coding Plan；按量付费为 `api.z.ai/api/paas/v4`，手改即可） | `https://api.z.ai/api/anthropic` |
| `opencode` | OpenCode Zen | `https://opencode.ai/zen/v1` | — |
| `deepseek` | DeepSeek | `https://api.deepseek.com` | — |

**新增内置提供商三步**：`presets.ts` 的 `PROVIDER_PRESETS` 加一行 → `common/types` 的 `ProviderKind` 加枚举值 → `providerIpc.ts` 的 `KINDS` 加同值。`urls` 缺某协议表示该家不支持，对应场景回退手填。

## 交互行为（`ProviderContent.vue`，CC Switch 式标签墙）

- 表单顶部「预设供应商」**标签墙**（`t-tag` 可点选，选中 primary + dark 高亮）：首枚 `自定义`，后接四家预设；空串 `''` 表示自定义（组件内部约定，非 null）。
- **Base URL 字段按需隐藏**：预设含当前协议端点时整个字段隐藏，地址以标签下提示行展示（「请求地址 …，只需填写 API Key」）；预设无该协议端点（如切到 openai-responses）或选自定义时字段恢复显示、手填（`presetUrl` 计算属性控制 `v-if`，与回填 watch 同一数据源）。
- **选中预设**：回填 protocol（按 `openai → anthropic → openai-responses` 顺序取该预设第一个有端点的协议）+ baseUrl；名称**为空、或仍是上一次预设带出的名称（未手改）**时跟随带出新 label，手改过的名称不覆盖（组件内以 `autoName` 标记自动带出值）；API Key 始终手填。
- **「获取 API Key」链接**：选中预设且该家有 `consoleUrl` 时，API Key 标签右侧出现链接；`target="_blank"` 经主窗口 `setWindowOpenHandler → shell.openExternal` 跳系统浏览器，无需额外桥。
- **已选预设时切协议**：预设含该协议端点则同步换 baseUrl，不含则保留现值（watch `form.protocol` 实现；四家均无 openai-responses 端点，切过去即手填场景）。
- **切回自定义**：只清 kind，已填字段全保留（改的是既有内置项的「摘牌」路径）。
- 保存：payload 带 `kind`（`form.kind || null`），走既有 `provider.create/update`。

## 列表展示（`index.vue`）

名称列改具名插槽：名称（truncate + title）后附 `t-tag`（outline small）显示 `PRESET_LABELS[kind]`，自定义不显示标签。

## 坑与约束

- **行内启停整行回传必须带 `kind`**：`index.vue` 的 `toggleEnabled` 把整行原样回传 `provider.update`，而 `updateProvider` 对 kind 是**显式写**（`input.kind ?? null`，为支持「内置→自定义」的清除）——漏带会把该行类型抹成 null。后续任何「整行回传 update」的新调用点都要注意。
- kind 与 `protocol` 正交且可改：类型只是标记，不锁定协议/URL；归档冻结规则（归档行不可编辑）对它同样生效。
- 余量查询（未来）：按 `kind` 分发到各家的额度查询 API（main 侧新模块，走 axios 直连 + 现有 `server.proxyUrl` 出站代理），对 kind = null 的行不可用。本期未实现。
