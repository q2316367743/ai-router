# 04 - 统计看板

> 2026-09-16。用量统计重构：聚合表扩展供应商/缓存/成功失败/耗时维度 + 新增小时聚合表，产出「首页统计看板」与「托盘弹出面板」双端视图。图表统一用 echarts（按需引入），口径与时间维度解析全部落在 main 侧 `usageRepo`。同日追加「模型速度折线（近七天）」——唯一不读聚合表、直接实时聚合 `request_logs` 的统计项。

## 为什么要重构

原 `usage_daily` 只有 `(date, public_model) → 请求数/输入/输出/总量`，而看板需要供应商拆分、缓存构成、成功率、平均延迟；这些维度只存在于 `request_logs`，但该表只保留 7 天，撑不起「近 30 天」。同时 `addUsageQuietly()` 只在请求**成功**时调用，天然算不出成功率。

因此改为：**聚合表补齐维度 + 统一写入路径 + 两表分粒度**。

## 表结构

| 表 | 粒度 | 保留 | 主键 |
|----|------|------|------|
| `usage_daily` | 天（`YYYY-MM-DD`） | 永久 | `(date, provider_name, public_model)` |
| `usage_hourly` | 小时（`YYYY-MM-DDTHH`） | 7 天（惰性清理） | `(hour_key, provider_name, public_model)` |

两表**列集合完全一致**（`usage.ts` 里共用 `usageColumns` 展开）：

`request_count`、`success_count`、`fail_count`、`duration_ms`、`prompt_tokens`、`completion_tokens`、`reasoning_tokens`、`cache_read_tokens`、`cache_write_tokens`、`unrecognized_tokens`、`total_tokens`

- 小时表只服务「今天」「近 24 小时」两个维度；日表服务「近七天」「近 30 天」。
- 小时表清理在 `accumulateUsage()` 内惰性执行（`DELETE WHERE hour_key <= 今天−7天`），无定时器。

## 统计口径（唯一权威定义）

口径全部集中在 `usageRepo.ts`，页面上不得另算一套：

| 指标 | 口径 |
|------|------|
| 成功 / 失败 | `status` 为 2xx 记成功，其余记失败（含本地拦截 400/401/404/502 与客户端断开 499） |
| 成功率 | `success_count / request_count`；无请求时展示 `—` |
| 平均延迟 | `duration_ms / request_count`，**含失败请求** |
| token 累加 | **仅成功请求计入**。失败请求 `usage` 为 null，且本地拦截的兜底估算值不应污染 token 统计 |
| 请求数 / 耗时 | 不分成败，一律累加（否则算不出成功率与真实平均延迟） |
| 缓存占比 | `(cache_read + cache_write) / total_tokens` |
| 令牌构成 | 输入 = prompt，输出 = completion，缓存 = cache_read + cache_write，无法统计 = unrecognized；占比分母为**四者之和**（保证合计 100%），进度条宽度以四维**最大值为 100%** |
| 缓存语义差异 | OpenAI 的 `cached_tokens` 是 prompt 的子集（缓存读 ⊆ 输入），Anthropic 的 `cache_creation/read` 独立计数。本看板的「缓存」= 读 + 写，与「输入」存在语义重叠，故仅用于趋势与占比观察，不与输入做加总校验 |
| 模型速度（token/s） | `sum(输出 token) / sum(耗时)`，**仅 2xx 且上游已返回用量**的请求。唯一读 `request_logs` 而非聚合表的指标，详见「模型速度折线」一节 |

## 统一写入路径

`proxyLog.recordRequest(entry)` 一次调用同时完成三件事（原 `recordLocalLog` + `addUsageQuietly` 两条路径合并）：

1. `recordLog()` → `request_logs`（详细日志，7 天；按 `request_id` upsert，回填 `startLog` 落下的 pending 行）
2. `accumulateUsage()` → `usage_daily` + `usage_hourly`（同一事务）
3. 成功后 `refreshTrayUsage()`（托盘标题即时刷新）

`unrecognizedTokens` 的兜底估算**只算一次**，日志与聚合共用。调用点共 8 处：`proxyHandler.ts`（6 处，含 400/404/499/502 与正常响应）、`protocol/convertHandler.ts`（1 处）、`proxyRouter.ts`（401 鉴权失败 1 处）。调用点无需再判断成败——成败与 token 取舍已在 `recordRequest` 内按 `status` 决定。

**聚合只在结束阶段累加**：转发路径在 `fetch` 上游前另有 `proxyLog.startRequest()` 落 pending 行（供日志页即时显示「进行中」），该阶段**不写聚合表**，因此聚合口径与改造前完全一致。应用退出 / 崩溃残留的 pending 行由启动时 `markPendingInterrupted()` 标为 499，**不计入聚合表**，故「日志条数」会略多于「统计请求数」。

## 时间维度解析

`resolveRange(range)` 在 main 侧把维度枚举解析为桶序列（渲染层只传枚举，不传时间戳，避免两端时钟口径分裂）：

| 维度 | 粒度 | 桶范围 |
|------|------|--------|
| `today` | 小时 | 今天 00:00 → 当前整点 |
| `last24h` | 小时 | 当前整点 −23h → 当前整点（24 个桶） |
| `last7d` | 天 | 今天 −6d → 今天（7 个桶） |
| `last30d` | 天 | 今天 −29d → 今天（30 个桶） |

> 两端候选维度为 **今天 / 近 24 小时 / 近七天 / 近 30 天**（窗口由小到大），默认选中 `last24h`。`today` 与 `last24h` 同为小时粒度、共用 `usage_hourly`，区别只在起点是「今天 00:00」还是「当前整点 −23h」。

**活跃度热力图窗口**独立于图表粒度，固定按天取数：`last30d` 用 30 天，其余维度回落 7 天（避免「今天」维度的热力图退化为单格）。

## 模型速度折线（从 request_logs 实时聚合）

首页看板末尾的「模型速度趋势（近七天）」是**唯一不读聚合表**的统计项，直接实时聚合 `request_logs`。

**为什么不用聚合表**：速度需要「成功请求的耗时」当分母，而两张聚合表的 `duration_ms` 累加**全部请求**（含失败），`completion_tokens` 却**只在成功请求时累加**——相除口径错配。本地拦截的 400/401/404 是瞬间返回（把速度抬高），客户端断开的 499 是长挂到超时（把速度压低）。`request_logs` 可以逐请求按 2xx 筛选，分子分母天然同口径；它的 7 天保留期又恰好等于需求窗口，因此**不需要新增列或迁移**。

**口径**（`speedRepo.ts` 的 `queryModelSpeed()`）：

| 项 | 定义 |
|----|------|
| 窗口 | 近七天（复用 `resolveRange('last7d')`，今天 −6d → 今天，7 个桶），与日志保留边界对齐 |
| 筛选 | `status ∈ [200,299]` AND `completion_tokens > 0` AND `duration_ms > 0`（进行中的行 `duration_ms` 为 NULL，天然排除） |
| 分组 | `log_date × provider_name × public_model`（对外模型名，与看板其余维度一致） |
| 速度 | `sum(输出 token) × 1000 / sum(耗时)`，即按 token 量加权的平均速度（token/s） |
| 取线 | 按窗口内 `sum(输出 token)` 降序取**前 5 条**（`SPEED_LINE_LIMIT`） |
| 缺失日 | 输出 `null`，折线断开而非画到 0，避免被误读为「速度为 0」 |

**已知限制**：

1. **上游不返回 usage 就没有点**：透传路径不强制 `stream_options.include_usage`，流式请求若上游不回 usage，`completion_tokens` 为 0（兜底估算只估请求正文的 prompt，不估 completion），这类请求会被筛选条件过滤，当天该模型显示为断点。非流式请求的 usage 一定在响应体里，通常不受影响。
2. **端到端口径**：`duration_ms` 含预填充、连接建立、网络与本地开销，prompt 长 / 输出短时数值偏低，反映的是体感速度而不是纯解码速度。真正的解码速度需要首 token 时间（TTFT），当前未采集。
3. **窗口滚动**：只近七天，第 8 天的点随日志清理一起消失，不能回看更长历史。要看更长的历史必须落聚合表并新增「成功请求耗时」列。
4. 只统计成功请求（2xx）。

**前端**：`UsageSpeedCard.vue` 自己取数——它的窗口与筛选都独立于 `useUsageStats`，所以不并入该 hook；托盘面板不渲染这张卡（`UsageDashboard` 的 `showSpeed` 开关默认关），也就不会产生这次查询。

## repo API（`usageRepo.ts`）

| 导出 | 说明 |
|------|------|
| `accumulateUsage(input)` | 日/小时两表同事务累加 + 小时表惰性清理 |
| `resolveRange(range)` / `activityDaysOf(range)` | 维度 → 桶序列 / 活跃度窗口天数 |
| `queryUsageOverview(query)` | **看板唯一入口**：一次查询产出总计、供应商拆分、模型拆分、时间序列、活跃度 |
| `queryUsageFilterOptions()` | 去重供应商/模型（取自 `usage_daily`，永久保留，供应商删除后历史仍可筛选） |
| `listUsageByRange(start, end)` | 明细表用，返回 `(date, provider, model)` 粒度原始行 |
| `queryModelSpeed()` | 模型速度折线（固定近七天，数据源是 `request_logs` 而非聚合表，见上一节）。**实现在同目录 `speedRepo.ts`**：它读的是日志表而非聚合表，口径自成一套，拆开也让两个文件都符合 RL-05 的行数约束 |

> 分组键是**名字快照**（`provider_name` / `public_model`），不是 id。删除供应商/模型不影响历史（无外键、读取不 join 主表）；**改名则按 id 同步改写历史行的名字列**，保证同一实体不裂成两组。机制与已知限制见 `../data/01-数据模型.md` 的「删除 / 改名与历史数据」。

`queryUsageOverview` 按粒度为日/小时切换聚合表，`groupBy` 复用同一套累加逻辑产出供应商与模型两个维度（按 totalTokens 降序）；`buildSeries` 用桶索引补零，保证数组与 `buckets` 等长。

### 托盘面板（`windows/tray/`）

独立渲染入口（`src/renderer/tray.html` → `windows/tray/main.ts`，`electron.vite.config.ts` 的 `rollupOptions.input` 多入口），复用 `UsageDashboard`（`compact` 模式 + 隐藏筛选）。维度与首页一致，均为 **今天 / 近 24 小时 / 近七天 / 近 30 天**，直接走组件的默认候选（`ranges` 无需显式传参）。

## 托盘行为与平台差异

`tray.ts`：

| 平台 | 左键 | 右键 |
|------|------|------|
| darwin / win32 | 切换统计面板（`trayPanel.toggleTrayPanel`） | `popUpContextMenu`（打开统计面板 / 打开主窗口 / 退出） |
| linux | — | `setContextMenu` 同样三项（多数桌面环境不派发 tray click 事件） |

> macOS 上**不能同时** `setContextMenu`，否则菜单会吞掉左键点击——这是面板方案的关键约束。

`trayPanel.ts` 要点：

- 无边框、置顶、`skipTaskbar`、不可调整大小，400×640；darwin `vibrancy: 'popover'`、win32 `acrylic`、linux 实色。渲染层的半透明叠加（面板底 / 卡片底 / 渐晕）见 `03-托盘.md` 的「面板外观：亚克力三层结构」。
- 单实例，隐藏而非销毁；`blur` 自动隐藏。
- 定位：按 `tray.getBounds()` 水平居中于图标下方；贴边回夹进 workArea；下方空间不足时改在图标上方展开。
- **竞态处理**：点击托盘图标时面板会先因失焦隐藏、随后 click 才到达，直接判断可见性会「关了又开」。用 `lastHideAt`（250ms 抑制窗口）吞掉紧跟隐藏后的这次点击。
- `win.show()` + `focus()` 必须成对：失焦自动隐藏依赖 `blur`，`showInactive()` 不会触发。

## 深浅色与多窗口

- 图表色值经 `tokens.ts` 从 CSS 变量读取，`isDark` 变化 → palette 重算 → option 重算 → `EChart.vue` 重新 `setOption`。
- `colorMode.ts` 新增 `storage` 事件监听：主窗口切换主题后，托盘面板即时跟随（两窗口共享同一个 localStorage key）。
- 托盘面板必须显式调用 `useColorMode()`，否则不会应用主题属性。

## 注意事项

- **改口径只改一处**：成功判定、token 取舍、缓存占比全在 `usageRepo` / `useUsageStats`，页面不得另算。
- **新增图表类型**：先在 `components/EChart/echarts.ts` 的 `use([...])` 中注册，再在 `options.ts` 加构造器。
- **迁移**：`usage_daily` 主键变更在 SQLite 需重建表，本项目为新建工程，`resources/drizzle/` 已整体重新生成（单一 `0000` 迁移，含全部 6 张表）。
- 概览页原「提供商/模型启用数」两张卡已被统计卡取代；`log:todayStats` 通道仍保留（`getTodayStats` 供其他场景）。
