# 14 - 托盘额度面板

> 2026-09-23。托盘弹出面板从「只有用量统计」升级为**两页分段切换**（用量统计 / 额度）：额度页按设置页配置的顺序与开关展示各提供商的余量快照，卡片沿用用量统计卡的解剖与分档色（按剩余百分比 / 余额阈值变色 + 右上角同色渐晕）。余量查询本身见 `11-余量查询.md`，面板窗口与亚克力外观见 `03-托盘.md`。

## 实现思路：三层，与看板卡片配置同构

```
common/types/trayQuota.ts（契约：有序 items + 余额告警阈值；键 = providerId）
        ↓ 与 quota.list() 合并（hooks/useTrayQuota.ts 的 resolveTrayQuotaItems）
windows/tray/components/TrayQuotaPanel.vue（每提供商整行一张卡）
        ↓ 卡内逐窗口一行：复用 components/quota/QuotaWindowRow.vue
TrayQuotaCard.vue（整卡渐晕取最紧张窗口）
        ↕ 持久化
setting 域通用通道（settings 键 tray.quota → setting:changed 全窗口广播）
```

- **零新增 IPC / 零数据库迁移**：托盘窗口用的是同一份 preload，`window.preload.quota`（list / refresh）与 `window.preload.setting` 直接可用。
- **配置与数据分开**：配置（顺序、展示开关、余额阈值）走 setting 通道；数据（快照）走 `quota:list`（读库不出站），只在用户点刷新或补查时才出站。

## 数据结构 / 契约

settings 表单键 `tray.quota`，值为 JSON 文本：

```ts
{
  items?: [{ providerId: string, visible: boolean }],   // 有序列表，顺序即渲染顺序
  balanceAlertThreshold?: number                        // 缺省 10
}
```

**合并规则（版本 / 数据变化安全）**：渲染序列 = 按存储顺序取当前已绑定策略的提供商 → 存储里没有的（新绑定）按 `quota.list()` 顺序追加且默认可见 → 未知 id（提供商已归档）与重复 id 丢弃。隐藏项保留位置，重新打开不漂移。与 `resolveCards`（看板卡片）完全同构。

**键用 providerId 而不是提供商名**：名字可改、可重名（`providers.name` 允许重名），改名后这里展示新名字、顺序不乱。

## 卡片规则（`TrayQuotaCard.vue`）

一张卡 = 一个提供商，**整行铺满**；卡内一个限额窗口一行进度条（opencode 3 行、zai 3 行…）：

| 快照形态 | 卡内呈现 | 整卡渐晕（分档色） | 页脚 |
|----------|----------|--------------------|------|
| 有窗口（primary / secondary / tertiary / extra） | **每个窗口一行**：窗口名 + 「剩余 x%」+ 带刻度的分段进度条（**填充长度 = 剩余**，每条按自己的剩余分档上色） | 最紧张窗口（剩余最少）的档位 | 余额（如有）· 套餐名（`identity.loginMethod`） |
| 无窗口但有 `cost.limit` | 一行「`cost.period` 或 限额」进度条（used / limit 比例） | 该比例的三档 | 已用 ¥x / 限额 ¥y · 套餐名 |
| 仅 `cost.balance`（DeepSeek 等） | 大数值余额（2 位小数，`¥` 走 statistic 前缀） | 余额阈值两档（< 阈值红 / 其余绿） | 套餐名 |
| 只有 `details` 分区 | 「—」占位 | 中性（无档） | 第一段前两行明细 · 套餐名 |
| 查询失败（`error` 非空） | 「—」占位 | 红 | 错误摘要（截 42 字），全文在提示气泡 |
| 从未查询 | 「—」占位 | 中性 | 等待首次查询 |

- **分界线是「有没有上限」**：有上限就有比例，就画进度条并按比例上色；只有纯余额（无 `limit`）才退化成大数值卡。
- 「不同百分比显示不同颜色」逐条落在进度条上（`QuotaWindowRow` 的 `fillColor`），整卡渐晕只负责「这一家有一个窗口告急了」的一眼可辨。
- 卡片头部的 `?` 提示气泡给「策略 X · N 分钟前更新」（逐卡的陈旧度在这里，面板顶部只给汇总）。
- 完整明细（`details` 分区、图表、账号 identity）仍只在主窗口「余量」页看，托盘卡片只做摘要。

## 分档与配色

| 判据 | 档位 | 类名 | 色值 / 渐晕来源 |
|------|------|------|----------------|
| 剩余 ≤10%（已用 ≥90%） | 告急 | `stat-poor` | `customer.less`：`--td-error-color-5` + `--td-error-color-1` 渐晕 |
| 剩余 ≤30%（已用 ≥70%） | 偏紧 | `stat-fair` | `--td-warning-color-7` + `-1` 渐晕 |
| 其余 | 充裕 | `stat-good` | `--td-success-color-5` + `-1` 渐晕 |
| 余额 < 阈值 | 告急 | `stat-poor` | 同上 |

- **进度条与文案同一口径**：填充长度 = 剩余百分比（剩余 100% 满格），颜色也按剩余分档 —— 条又短又红就是快用完了；`QuotaWindowRow` 与余量页逐像素同一实现。
- 窗口进度条的填充色取 `quotaWindowSeverity` 映射到 `--td-error-color` / `--td-warning-color` / `--td-brand-color`（`QuotaWindowRow` 内）。
- 卡片根节点的分档类只用于**右上角同色渐晕**（与「请求数」那些卡片完全同一套 `.metric-card` + `stat-*`）；卡内文字各自显式取色，不会被整卡档位带偏。
- 面板已把 `--metric-tint-alpha` 降到 60%、卡片底指向玻璃底，额度卡自动跟随（见 `03-托盘.md` 的亚克力三层结构）。
- 阈值方向与余量页进度条一致（`QuotaWindowRow.vue` 的 `fillColor` 也改用 `quotaWindowSeverity`），两处不再各写一遍 90 / 70。

## 交互与刷新

| 时机 | 行为 |
|------|------|
| 面板弹出（`tray:shown`） | `quota:list` 读库渲染（毫秒级、**不出站**） |
| 切到额度页（首次挂载） | 同上；随后对「从未查到结果（`queriedAt === null`）且提供商启用」的项逐条补查一轮 |
| **页面开着不动（每 60 秒）** | `useIntervalFn`（VueUse）重读一次 `quota:list`：余量是后台每 10 分钟刷一轮，页面得自己跟读；同一拍把时钟基准 `now` 走一格，驱动顶部「更新于 X 分钟前」重算（`relativeTime(ms, now)` 显式传基准，否则文案会停在打开那一刻）。窗口隐藏时 Electron 会自行节流定时器，切页/卸载时由 `useIntervalFn` 自动停表 |
| 补查去重 | 模块级 Set 记录本窗口会话已补查过的 providerId，**每提供商最多一次**（失败也不反复出站） |
| 手动刷新 | 顶部 `refresh` 按钮 → `quota:refresh`（全量出站，20s 超时在 main 侧），失败弹 `MessageUtil.error` |
| 设置页改动 | 即改即存 → `setting:changed` 广播 → 托盘面板重读配置 → 实时重排 / 变色（阈值同样即时生效） |

**两页用 `v-if` 而不是 `v-show`**：额度页只在真正切到该页时才挂载，补查不会在「面板一创建」时就白跑一次出站请求；同时避开 echarts 在 `display: none` 容器下尺寸为 0 的问题。

## 注意事项 / 已知限制

1. **停用的提供商不展示**（`providers.enabled = false` 不参与余量查询，快照会变陈、展示出来是误导）。设置页仍列出它们并标「已停用」，顺序与开关配置保留，重新启用后原样回到原位。
2. 顶部「更新于 X 分钟前」取展示项里**最旧**的一条（最保守口径）；逐卡时间在卡片提示气泡里，不逐卡显示。
3. 已归档提供商的配置项在下次保存时被丢弃（与看板卡片处理未知 id 一致）；恢复提供商后落到列表末尾。
4. 余额阈值**不分币种**：¥10 与 $10 视为同一数值口径 —— 快照里币种不统一时这是已知的粗糙点。
5. 卡片整行铺满、高度随窗口数增长（opencode / zai 三条 ≈ 200px）：提供商多了面板就要滚动 —— 面板窗口固定 640px 不可拉伸（`trayPanel.ts`），这是「卡内逐窗口一行」的必然代价。
6. 托盘额度页不复用 `cardRegistry`：卡片数据源是余量快照而非用量统计 `ctx`，两者只共用外壳（`MetricCard`）与分档色；窗口行则直接复用 `components/quota/QuotaWindowRow.vue`（余量页同一组件）。
