# 06-应用图标

> 2026-09-16。记录应用图标（打包图标 + 系统托盘图标）的落点、尺寸与重新生成方法。

## 落点一览

| 文件                 | 尺寸      | 用途                                                                                          |
|----------------------|-----------|-----------------------------------------------------------------------------------------------|
| `build/icon.png`     | 1024×1024 | electron-builder 打包主图（`buildResources: build`，多平台兜底）                              |
| `build/icon.icns`    | 16~1024   | macOS 应用图标（Dock / Finder / 安装包）                                                      |
| `build/icon.ico`     | 16~256    | Windows 应用图标（exe / 任务栏 / 快捷方式）                                                   |
| `resources/icon.png` | 256×256   | **托盘专用**图标（儿童机器人）：`src/main/src/app/tray.ts:11` 经 `?asset` 引入，缩放到 16px（@2x 32px）作系统托盘 |

- electron-builder 无需在 `electron-builder.yml` 里显式声明 icon：默认取 `build/` 目录下的 `icon.icns` / `icon.ico` /
  `icon.png`。
- `build/` 三份图标内容一致，为 **不透明满底方形**（无 alpha）；macOS 会自行套圆角蒙版，因此源图不需要预挖圆角。
- **`resources/icon.png` 与 `build/` 图标已不再一致**：它是独立的透明底彩色机器人图（菜单栏无底色），仅托盘使用，重生成应用图标时不要覆盖它。

## 设计约束（换图时注意）

- 原图必须 **正方形**，且主体尽量居中：图标在 Dock / 任务栏会被缩小到 16px，偏心构图会明显失衡。
- 深色满底图在圆角蒙版下会形成「深色方块」，边缘容易显脏；如换图建议主体外扩、减少纯留白。
- 托盘图（`resources/icon.png`）为 **透明底**，且需贴近画布边缘：建议按非透明像素外接框裁掉四周留白，否则缩到 16px 后主体偏小。当前图由 256×256 源按 alpha 外接框加 6px 边距裁成正方形后再缩放到 256。

## 重新生成步骤

```bash
SRC=/path/to/source.png            # 要求 ≥1024×1024，正方形
T=/tmp/icon-work && mkdir -p "$T" && cd "$T"

# 1) 居中放大裁切（示例：2000² → 1800²，向右下锚定去掉多余背景）
sips -s format png "$SRC" --out base.png
sips -c 1800 1800 --cropOffset 100 200 base.png --out crop.png

# 2) 主图（1024 给 build；托盘图 resources/icon.png 另行处理，见下方「托盘图」）
sips -s format png -Z 1024 crop.png --out build-icon.png

# 3) macOS .icns（iconset 文件名是 iconutil 的硬约定）
rm -rf icon.iconset && mkdir icon.iconset
for spec in 16:icon_16x16 32:icon_16x16@2x 32:icon_32x32 64:icon_32x32@2x \
            128:icon_128x128 256:icon_128x128@2x 256:icon_256x256 \
            512:icon_256x256@2x 512:icon_512x512; do
  s=$(echo "$spec" | cut -d: -f1); n=$(echo "$spec" | cut -d: -f2)
  sips -s format png -Z "$s" crop.png --out "icon.iconset/$n.png" >/dev/null
done
cp build-icon.png icon.iconset/icon_512x512@2x.png
iconutil -c icns icon.iconset -o icon.icns

# 4) Windows .ico：本机无 ImageMagick，用 Node 把各尺寸 PNG 直接打包成 ICO
#    （Vista+ 支持 ICO 内嵌 PNG，尺寸 16/32/48/64/128/256，256 的宽高字段写 0）
for s in 16 32 48 64 128 256; do
  sips -s format png -Z "$s" crop.png --out "ico-$s.png" >/dev/null
done
node make-ico.mjs . icon.ico     # make-ico.mjs 见下方要点
```

`make-ico.mjs` 结构（约 30 行）：先写 6 字节 `ICONDIR`（`0, 1, count`），再为每张图写 16 字节 `ICONDIRENTRY`（宽高 256 时写 0、
`planes=1`、`bitCount=32`、数据长度、偏移），最后按目录顺序拼接各 PNG 原始字节。

## 托盘图（`resources/icon.png`）

与 `build/` 图标分开维护：透明底、按非透明像素外接框裁成正方形并留 6px 边距，最后缩放到 256×256 覆盖
`resources/icon.png`。本机用 Python + Pillow 处理（无第三方依赖风险）：

```bash
python3 - <<'PY'
from PIL import Image
src = Image.open('源图.png').convert('RGBA')           # 建议 ≥256×256，透明底正方形
x0, y0, x1, y1 = src.split()[3].getbbox()              # 非透明像素外接框
side = max(x1 - x0, y1 - y0) + 12                       # 两侧各留 6px
cx, cy = (x0 + x1) // 2, (y0 + y1) // 2
box = (cx - side // 2, cy - side // 2, cx + side // 2, cy + side // 2)
src.crop(box).resize((256, 256), Image.LANCZOS).save('resources/icon.png')
PY
```

## 注意事项

- `sips` 输出 **不会自动改格式**：从 jpg 转 png 必须显式 `-s format png`，否则会得到「.png 后缀的 JPEG」，`iconutil` 会直接报
  `Failed to generate ICNS`。
- `--cropOffset` 顺序是 `offsetY offsetX`，相对左上角。
- 本项目不需要 `sharp` / `png-to-ico` 等依赖，上述系统命令 + 内置 Node 即可完成。
- 托盘图为彩色图、非 template image，深浅色菜单栏下不自动变色；如需适配可另出单色 + alpha 的 template 版本。
