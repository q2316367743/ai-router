# 07 - 开机自启

> 2026-09-16。设置页可开关开机自启；开启后系统登录时**静默驻留托盘**（不建主窗口），代理服务自动在后台运行。
> 状态以操作系统登录项为唯一权威，不做本地持久化。

## 实现思路

- **单一真理源**：不落库、不写 `settings` 表。开关状态每次读 `app.getLoginItemSettings().openAtLogin`，
  与系统设置（macOS「登录项」/ Windows「启动应用」）实时一致，避免用户手动改动后 DB 与实际不符。
- **静默启动**：登录项拉起时 `createMainWindow()` 不执行，只 `registerAppTray()`；macOS 额外 `app.dock?.hide()`
  （无主窗口时 Dock 图标不应常驻）。用户点托盘图标或再次启动应用即可唤出主窗口。
- **能力门禁**：`app.isPackaged && (darwin || win32)` 才认为支持。未打包（`npm run dev`）时若调用
  `setLoginItemSettings`，会把 Electron 可执行文件写进真实登录项，污染系统，故一律返回 `supported: false`，
  渲染层开关置灰并提示「安装到系统后生效」。

## 平台差异（关键）

| 关注点 | macOS | Windows |
|--------|-------|---------|
| 是否支持 | 是（`mainAppService`） | 是 |
| `args` 透传 | **不支持**（`args` 为 Windows 专属） | 支持，写入 `--hidden` |
| 登录启动判定 | `getLoginItemSettings().wasOpenedAtLogin` | `process.argv.includes('--hidden')` |
| 读写一致性 | 无需额外参数 | **读时必须传与写时相同的 `path` / `args`**，否则 `openAtLogin` 判定不准 |
| 签名要求 | 未签名 / 未公证可能静默失效（系统限制，代码无法绕过） | 无 |

> Electron 在 v44 移除了 `openAsHidden` / `wasOpenedAsHidden`（本项目 Electron 39 虽仍有但已废弃），
> 因此不使用该字段，改以上表的 `wasOpenedAtLogin` / `--hidden` 方案。

## 数据契约

`@common/types`（`src/common/types/app.ts`）：

```ts
interface AutoLaunchState {
  /** 当前运行形态与平台是否支持自启（未打包 / 非 mac、win 为 false） */
  supported: boolean
  /** 系统登录项中当前是否已启用 */
  enabled: boolean
}
```

IPC（`app:*`，写入后回读真实值返回）：

| 通道 | 入参 | 返回 |
|------|------|------|
| `app:getAutoLaunch` | — | `AutoLaunchState` |
| `app:setAutoLaunch` | `enabled: boolean` | `AutoLaunchState` |

preload：`window.preload.app.getAutoLaunch()` / `window.preload.app.setAutoLaunch(enabled)`。

## 启动链路

```
系统登录
  → macOS: wasOpenedAtLogin=true / Windows: argv 含 --hidden
  → isOpenedAtLogin() === true
  → registerAppTray() + app.dock?.hide()（darwin）
  → 不建主窗口（代理服务已由 startProxyServer() 后台启动）
用户点托盘「打开主窗口」/ 再次双击应用（second-instance）
  → showMainWindow()
```

日常冷启动（非登录项）不受影响：走原逻辑 `createMainWindow()` 正常显示主窗口。

## 注意事项

- **开发模式开关必然置灰**：这是刻意设计，不是 bug。要验证需 `npm run build:mac` / `build:win` 出安装包后测试。
- 关闭自启走同一接口（`openAtLogin: false`），会移除系统登录项。
- Windows 上 `getLoginItemSettings` 需传与设置时相同的 `path` / `args`，否则即使用户已在系统启动项里启用也会读成 `false`；
  `loginItemQuery()` 统一处理，勿在别处另写一份。
- `second-instance` 监听是静默驻留可用性的必要配套：否则应用驻留托盘时用户再次双击图标不会有任何反馈。
