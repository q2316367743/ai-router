# 12 - 看板卡片可配置（显示 + 位置）

> 2026-09-19。首页与托盘面板共用的统计看板（见 `04-统计看板.md`）支持**按界面独立配置每张卡片的显示/隐藏与排列顺序**：配置入口在**设置页「看板卡片」卡**（首页/托盘分段切换 + 拖拽排序 + 开关，改动即改即存），看板本身是纯展示面、不放任何编辑元素（用户反馈：展示页放编辑很诡异，且托盘窄面板下头部按钮换行独占一行）。

## 实现思路：三层架构，新增卡片零配置代码

```
cardRegistry.ts（卡片清单：唯一事实源，数组顺序 = 默认顺序）
        ↓ 按 surface 过滤 + 与存储配置合并（useDashboardLayout）
UsageDashboard.vue（纯注册表驱动：单 grid 渲染，模板不写死任何一张卡）
        ↕ 持久化
setting 域通用通道（settingRepo → settingIpc → preload.settingApi → setting:changed 广播）
```

- **加新卡片** = 实现一个只收 `ctx` 的卡片组件 + 在 `cardRegistry.ts` 追加一行定义；布局配置的合并、设置页配置清单、跨窗口同步全部自动生效。
- **id 是持久化键，注册后不可改名**（改名等于换卡，用户已有配置会失效）。

## 数据结构 / 契约

**存储**：settings 表单键 `dashboard.layout`，值为 JSON 文本：

```ts
{ home?: { id, visible }[], tray?: { id, visible }[] }
```

**合并规则（版本升级安全）**：渲染序列 = 按存储顺序取已注册卡片 → 注册表新增而存储缺失的卡片**按注册表顺序追加**并取 `defaultVisible` → 存储中未知 id（卡片已下线）与重复 id 丢弃。顺序**包含隐藏卡**（隐藏卡保留位置，重新打开不漂移）。无存储配置时 = 注册表默认（全部可见、注册顺序，与旧版硬编码模板视觉一致）。

**卡片统一 props 契约**：所有看板卡片只收 `ctx: DashboardCardContext`（`{ stats, compact, speed, clients }`），数据自给自足从 ctx 取；统计卡另收静态 `extraProps: { cardKey }`（`useUsageCards.ts` 的 `buildStatCardConfig(stats, cardKey)` 派生展示配置，卡片内部 computed 包裹保持响应性）。

**栅格跨度**：`span: 'cell' | 'half' | 'full'` —— cell 占 1 格；half 半行（首页 4 列下 `col-span-2`、托盘 2 列下恰为半行无需跨列），成功率环形 / 缓存占比环形两张卡并排半行（与旧版嵌套 2 列 grid 等价）；full 整行（`col-span-full`）。**不用 dense 流**：用户隐藏卡片留下的空位如实呈现，不重排后续卡片。统一 gap 10px。

**卡片清单**（id → 卡片，`surfaces` 限定界面）：`stat-requests` / `stat-success` / `stat-latency` / `stat-tokens`（cell）、`trend`、`provider-trend`（仅小时粒度有数据，卡内自渲染 null）、`activity`、`composition`（full）、`ratio-success`、`ratio-cache`（half，由原 `UsageRatioCard` 拆分，该文件已删除）、`provider-bar`（full）、`clients`、`speed`（**仅 home**：数据仅首页取数且窄面板放不下，托盘配置列表中不出现）。原 `showSpeed` / `showClients` props 已删除，界面约束改由注册表 `surfaces` 声明。

## 交互与同步

- 编辑器**即改即存**：开关切换、拖拽结束、恢复默认都立即 `saveDashboardLayout`（本地 ref 生效 + 落库 + 广播），没有「保存」按钮、也就没有切换「首页/托盘」时的未保存草稿问题；「恢复默认」有成功提示。
- 广播到达另一窗口（如主窗口设置页保存后仍存活的托盘面板）→ 该窗口 `useDashboardLayout` 的订阅重读配置 → 看板实时重排（保存窗口自己也会收到广播，重读同值无副作用）。
- 编辑器 `onMounted` 先 `await ensureLayoutLoaded()` 再进编辑模型：配置未落地时读到的默认顺序一旦改动保存，会**用默认布局覆盖用户配置**——这是唯一的时序坑。
- 看板本体不等待配置：未加载完成前按注册表默认渲染（本地 SQLite 毫秒级读取，无可感知闪烁）。
- 全部卡片被隐藏时看板显示一行指引「暂无显示中的卡片，可在主窗口设置页『看板卡片』中开启」。

## 注意事项 / 已知限制

1. **新增卡片步骤**：写卡片组件（props 只收 `ctx`，必要时 `extraProps`）→ `cardRegistry.ts` 追加定义（新 id！）→ 已有用户会自动在列表**末尾**看到新卡（默认可见性）。统计类新指标另见 `09-看板卡片规范.md`（阈值判定仍在 `useUsageStats`）。
2. **下线卡片**：从注册表删除即可，残留的存储 id 在合并时被静默丢弃。
3. **界面扩展**：未来新窗口加进 `DashboardSurface` 联合类型 + 注册表条目的 `surfaces`，即可复用同一套机制。
4. 设置走通用 `setting:get/set` 通道——后续外观等 UI 偏好可迁移至此（本次未迁移，改动保守）；键约定以域名为前缀（如 `dashboard.layout`）。
5. sortablejs 为 tdesign 的传递依赖，本次已显式声明为直接依赖（`@types/sortablejs` devDependencies）。
